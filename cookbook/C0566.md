# A rename batch over generated-marked build inputs and the frozen worklist

Problem: rename_sym skips files whose first 3 lines say `generated by tools/<x>` and prints a regenerate
command instead. Share headers src/shared/{ov,multi}/cls_*.h carry `generated by tools/share_body.py`, but
share_body is not a regenerator: a rename called from a cls header left 12 stale-build-input hits (3.43 T2
worktree demo of func_80029178). The build would break.

Fix (3.43 T2, 4c72a67ad5): `regen_cmd` returns None for `src/` and `include/` (build inputs are always rewritten
as text) and for rename_scan.TEXT_GENERATED (docs/leverage.md/.tsv: rewritten as text, regenerated once at the
phase close). The header's own `regenerate: <cmd>` is the printed command (GEN_RE alone was greedy).

Frozen records: config/names_worklist.tsv is in rename_scan.HISTORY, so its `name` column keeps the placeholder
the `--worklist` no-evidence check compares against; neither tool rewrites it.

Check a batch:
- `rename_sym.py --spec B.tsv --task T<n> [--dry-run]` (--task required; history gets `<old> (<phase> T<n>)`).
- regenerate every printed `regenerate:` line in the main tree (docs/progress.md needs `make report`, so a
  worktree demo cannot clear it), then `rename_scan.py --spec B.tsv` 0 stale 0 unclassified.
- `rename_scan.py --worklist config/names_worklist.tsv [--complete]`: instances from .run/sig.*.jsonl by full
  h_exact, names through the splat yamls' symbol stacks; a class spec row writes one names.tsv row, scope class:<id>.
