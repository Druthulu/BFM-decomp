# C0512 — Folding duplicate struct definitions onto one canonical type, byte-safely

## Folding duplicate struct definitions onto one canonical type, byte-safely (P38 T4-T6)

- An opaque-tier fold renames members, so rename ACCESSES in every file the definition reaches (includers, their
  sibling headers, macro bodies), type-aware by base; otherwise the judge sees compile errors, not layout verdicts.
- Tier 1 = same MEANINGFUL member names; placeholder names (`unk*`, `f*`, `w*`) differ and still need respell.
- Member respell pools candidates across all classes in one run: fold classes that share member names in separate
  runs, with disjoint respelled member sets.
- A whole-member use (`f(x.v)`) cannot be respelled: choose as canon the spelling the whole-member users have.
- A class can need a member-type twin folded first (a one-line alias of 2 names, not the whole class).
- For a definition already matching a PsyQ SDK layout and names, rename by hand and alias the old name; re-emitting
  the SDK body loses offset comments and SDK pad names can break the pad invariant.
- A prototype conformed in a shared per-function header must be conformed in every includer at once (one unit per
  callee), else header and TU conflict.
- Local copies become `typedef <Canon> <Local>;` aliases; every fold is judged by the byte gate, never assumed neutral
  (cast->member rewrites move scheduling via MEM_IN_STRUCT_P, C0507).
Tools: `tools/lift_types.py --census/--fold*`, `tools/restruct.py --rung L --only`, `tools/struct_twins.py` (BFM).
