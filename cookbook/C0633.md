# Value folds and field retypes after absorption: what blocks them

Context: 3.45 T17.c18 (batch F folds onto PsyQ value types; the player +0x20 field retype; a08bbcb1f8..c1694389f1).
- This repo's `VECTOR` is 12 bytes (3 x s32), not PsyQ's 16 (with pad): a 16-byte value copy cannot fold onto it.
- A fold applied INTO a type that is itself a fold target in the same batch leaves the gate red until that row is
  stamped (the chain resolves only through `applied:`): gate after the stamp commit, not before.
- Rung T field key (`((Holder *)x)->f` retyped to `T *`) needs T defined before the holder (move the definition first).
- A field read 2,361 times (player +0x20) stays PENDING in rung T: `t_member_uses` (restruct.py:9229) turns each cross-file
  `(u8 *)` respell into a pending entry (1,690), plus s32 locals (332), other pointer locals (~150), integer args (~30):
  typing a hub field is a campaign (engine change + its local keys first), not a batch.
- Byte refusals seen: a 32-byte copy view spelled member-wise as MATRIX grows the frame (128 -> 144) and splits s32 word
  stores into s16 pairs (wall, COUNT); a block used both for word copies and as a CdSearchFile record is a mixed object
  (the MATRIX hand-fold failed to build in 147 binaries).
