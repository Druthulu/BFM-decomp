# Exact layout twins: alignment attributes are load-bearing and not in the layout hash

struct_layout.layout_hash hashes (size, leaves) only. Two definitions with the same leaves but different
`__attribute__((packed, aligned(1)))` / `aligned(8)` hash as one exact twin class, yet folding the packed one into the
aligned one changes how struct copies compile (lwl/lwr vs lw; a comment at ov_SC02_017_jr_8017DF34.c:4092 says the match
depends on it). P3.45 T7 reviewers (r1 V048 W4, r2 V009 BlockData, r5 V005 UnalignedPair, r8 V013 Rec801806C8_s and V001
Mtx_A8CE0) split such members off: parts of 2+ with the same attributes fold among themselves, a lone member goes to
tracing with the attribute's file:line as the cite.
Check: `grep -n 'packed\|aligned(' <def line>` for every member before choosing a class target; never fold across attributes.
Also seen: classes whose members' field lists differ only by fields sitting in each other's tail/inner padding hash alike;
the fold target must take the union of the fields (the engine's merged definition).
