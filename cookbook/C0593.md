# Asm-label definitions are invisible to name-keyed signature tools

- `s32 func_80188250_body(s32) __asm__("func_8018035C"); s32 func_80188250_body(s32 a0) {…}` defines func_8018035C in
  that binary. A tool keyed on C names (argcheck definitions()) misses it and resolves a declaration of func_8018035C to
  another overlay's same-named body: false return/arity "lies" appear when the declaration is made correct.
- Fix pattern: register an alias body under its label (after SHARED_FN binds; a label can reach its body through a bound
  header). 3.44 T5.c7: argcheck `_ALIAS`, read by resolve_definition_ret only.
- Trap: feeding alias bodies to the arity resolver too unmasked 7,701 real own-binary arity rows (func_80161208 alone
  7,423: its only body is the alias aF80161208); restricting to labels with another body still showed 106. Measure the
  row delta before widening a resolver; hidden true rows belong to the arity task, not the return fix.
- share_census.mask_text keeps string literals (the label survives) but changes text length: scan masked text, not raw offsets.
- Related: C0223, C0588 (asm-label prototypes), C0592.
