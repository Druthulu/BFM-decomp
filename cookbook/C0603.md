# C0603 — Old tool vs new tool on the same inputs: split a generated-doc diff into change and input drift
tags: generated-docs,leverage,neutrality,drift,check · date: 2026-11-13 · phase/task: 3.45/T1 · origin: -

Symptom: a tool edit's "the generated output stays byte-identical to HEAD" check fails (3.45 T1.c2: docs/leverage.tsv differs at line 27 after an additive leverage_rank change).

Mechanism: the committed generated doc was last regenerated at an older commit (leverage.tsv at f88462bafc, 3.44 T15); its inputs (the census over src/include, 4,576 files changed since) moved under it. HEAD's doc is stale against HEAD's inputs, so "identical to HEAD" mixes the tool change with input drift.

Move: separate the two variables on the same inputs. Run HEAD's tool (`git show HEAD:tools/<tool>.py > .run/<phase>/<t>/old.py`, run it with the repo's tools dir on sys.path, or check out into a scratch worktree, C0546) and the new tool on one census; byte-compare their outputs. Identical => the change is neutral; the diff against the committed file is drift, and the regenerated doc is committed with the tool change (its own `--check` then passes).

Rule of thumb: before promising "byte-identical to HEAD" for a generated doc, run the tool's `--check` at HEAD first; a DIFFERS there is drift to commit separately.
