# Applying many struct folds with restruct --fold-row: costs and engine walls (P3.45 T7.c2)

- `--fold-row --write` refuses when any file it touches is dirty (restruct.py fold_write ~:4340), and every fold touches
  the header: without a batch mode a batch is one commit per component (91 rows took ~3.8 h). Gate once per batch with
  `scratch_cmp --rev <batch base>` (fleet-wide ~4m50s), then one gate commit and one stamp commit.
- Engine refusals seen on 148 T2 link rows (57 refused): sign conflict at one offset (19; T6's plan is a named union, the
  engine refuses instead), member token before the target's definition (5), bit-field target (2), attributed target (2),
  load-bearing size (2), PsyQ target whose layout differs (1); IndexError in `_hf_file_edits` on trees reached after other
  folds (4).
- Cross-header alias respelling: an alias typedef in include/struct_types.h respelled to a target defined in a header
  included later (src/shared/engine_types.h) breaks every object; the "member before target" check is per file only.
- The renderer treats a field literally named `pad` as padding (`s32 vx, vy, vz, pad;` → `u8 padC[0x4]`), which can create
  a new dup class (Slot16 + Vec32); restore the definition by hand and re-run the gates.
- `struct_twins --dispositions` adds a new row for a shifted `Name@file:line` key instead of rekeying; rekey by hand.
- A revert commit does not undo respellings in the untracked restruct ledger.
