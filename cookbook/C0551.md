# Ghidra type rows: import order and spelling traps
- ImportAnnotations shell pass: a `typedef` row whose base sorts after it (TreeMap path order) throws out of run() unless composite shells are made first, then typedefs in dependency rounds (fixed T7.c1).
- Union bodies must be filled before structs that embed them (dependency order), else the struct component gets a 1-byte/zero union.
- `T[a][b]` must be built innermost first (ArrayDataType of T[b], count a); the old suffix loop built T[b][a].
- Bitfields: export adds `bits`,`bitoff` on bitfield components only; import via `insertBitFieldAt` (non-packed) / `addBitField` (packed, unions).
- Header comment re-alignment: type_census `mask_text` blanks directive lines, so map masked statements back to raw text line by line before reading trailing comments (an off-by-one shifted every field comment).
- struct_layout `_split_declarators` drops arrays of function pointers `T (*f[3])(...)` and the 2nd+ declarators of a comma bitfield `u8 x:3, y:5;`: re-read members with cdecl.parse and fail on any dropped one (ghidra_types `_fill_dropped`, T7.c2).
Source: P3.41 T7.c1; tools/ghidra_types.py, tools/ghidra_scripts/ImportAnnotations.java.
- The rebuild proof checks that Ghidra reproduces the rows exactly, not that the layout is correct. A self-consistent mutation (a field moved into padding) still passes, so pair it with `ghidra_types.py --gcc-compare` on the `.after.jsonl` export (gcc DWARF). Mutation controls use `BFM_TYPES_FILE=<scratch copy>` (T7.c3).
- Proof wall times (Ghidra 12.1, WSL): resident 77 s, overlays ~172 s, exes ~207 s, including 6.5k type rows on main.
