# Giving a return-less non-void def a real `return` without moving bytes

Find them: mask comments/strings/preproc, take depth-0 `type name(params) {` heads (K&R decls allowed), keep non-`void` return types whose masked body has no `\breturn\b` or has a bare `return;` (docs/ops/p343-t3-return-less-nonvoid-scan.md, 3.43 T3; scanner .run/3.43/t3/scan.py scratch).

Ladder, measured on 40 defs (3.43 T3.c1, 21 neutral / 19 not):
- Tail call to a non-void callee: `return f(...);` is neutral ($v0 already holds f's result). Most of the 21.
- Tail value already loaded into $v0 (e.g. an `lhu` feeding stores): `return <that global/load>;` is neutral; returning a narrower local copy adds `sll/sra`.
- Value computed earlier into a local: `r = f(); ...; return r;` is neutral when r stays in $v0; a `register` local can replace a `!FAKE` keepalive asm.
- Tail call to a void callee: `return 0;` (or any constant) adds `move/li v0`: no neutral form; never retype the callee (that is a lie). Comment instead.
- Empty body: `return 0;` fills the `jr ra` delay slot with `li v0,0`: not neutral.
- Tail store of a constant (`x->f = 1;`): `return 1;` or `return x->f = 1;` adds `li v0,1`.
Comment form at the def: `/* $v0 at exit: <what>; no byte-neutral return: <form> moved <insn> at +<off>, <binary> objdump */`.
Gate: scratch-compile every TU that defines or #includes the target against a HEAD baseline (shared headers fan to ~140 TUs), then R22.
Keep line counts: put `return X;` on the existing last statement's line (`stmt; return X;`).
