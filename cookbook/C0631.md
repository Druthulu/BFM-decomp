# Map call arguments to callee parameters: a struct returned by value shifts every argument by one

Context: 3.45 T17.c16 (tracing which object a callee's parameter receives, for per-source absorbs).
- A callee that returns a struct by value receives a hidden pointer to the result as its FIRST argument ($a0); the C
  arguments shift by one register. A tracer that maps arguments by C position puts the caller's object on the wrong
  parameter (c16: `func_8018020C` a2 got the actor; it is `a0+0x102`; ov_SC05_007_jr_8017BEBC.c:4429 vs definition :4763).
- Check the callee's definition return type before mapping positions; audit any earlier arg-position tracer the same way.
- Bare `KR_AS(T, f)()` calls with no argument pass whatever $a0 holds: only trust them when no temporary is placed in $a0
  before the call (read the code asm, not only the C).
- A shared-body node that pools the kinds of every overlay can decide a copy whose own overlay has no reaching kind:
  require own-overlay evidence before moving such a source.
