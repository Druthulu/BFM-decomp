# Many-name grep over src: GNU grep over git ls-files, not git grep -F -f

Problem: a per-unit evidence scan needs every line in src/ and include/ (337 MB, ~10k files) that mentions any of ~800-1,400 names.
- `git grep -F -w -f names.txt -- src include` took 265 s for 777 names (3.43 T6.c1): git grep's many-pattern fixed-string path is slow.
- `git ls-files src include | xargs grep -n -w -F -f names.txt` (GNU grep, Aho-Corasick) does the same in about 2 s for 1,346 names.
- One grep pass, then bucket hit lines per name in Python; a 500-unit dossier run went from est. hours to 25 s.

Trap: splat emits `.asciz` for any 4-byte word that happens to be printable (e.g. "ENE" = 454E4500 in every overlay). Treat strings under 4 chars as no string evidence.
