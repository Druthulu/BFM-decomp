# C0543 — Return-type changes: def+decls+callers as one unit; the return type is a caller byte fact
tags: declarations,return-type,lying,bytes,rung-D · date: 2026-11-07 · phase/task: 3.40/T13 · origin: P3.40 T6 summary

Changing a function's return type across a fleet (3.40 T6, legacy-T7 return lies).

- The def and every decl change as one unit. A def retyped alone makes every old `extern` decl in its includer TUs a "conflicting types" error. Edit the def, all decls and all callers together, and judge with `make check-all` (rung D refuses def-TU `--with` and cannot edit thousands of decl TUs as one unit).
- The return type is a byte fact at the caller: a `u8` decl of a function the caller reads as `s32` adds or moves an `andi 0xff` at the call (func_80014CF8, ov_MAIN_012 jr_801458E0.o). A return that "matches today" can depend on the lie.
- A return is real when the def's return path sets `$v0` and a caller uses it. Pass-through wrappers declared `void` hide a real return (func_8016130C: 1,213 `extern void` decls vs an s32 def).
- `type_census` lying counts only parameter lies (argcheck); return mismatches are invisible to it, so lying=0 does not mean no return lies.
