# Residue coverage is per site; re-run after any respelling task

A coverage check keyed on "body has any ledger row" hides per-site gaps once later sweeps add rows for other reasons: match per site (form, normalised base, off). Merge new residue entries into the latest row rather than superseding it (a superseding row unbacks earlier KEPT entries). A per-site gate goes red again when a later task respells a covered body (new site keys): re-run `restruct --residue` per segment after any respelling task, before the milestone.
