# KR_AS: give a `()` callee its one prototype; mark the shipped short/over calls

- 3.44 T6: `KR_AS(T, fn)` (include/common.h) = `((T (*)())(fn))`, an unprototyped view of fn. Calls through it keep the
  old `()` semantics exactly (default promotions, no arity check, direct `jal`), so a `()` declaration can take the
  definition's prototype while a call whose shipped caller passed a different count stays byte-true.
- Ledger config/kr_view_casts.tsv `callee def_file cause task cites`, one row per callee; `sig_evidence --check` re-decodes
  cites (callee read of the missing arg reg/slot + the short caller's `jal`), every KR_AS site needs its (fn) row;
  type_census counts KR_AS as KEPT class KR-VIEW. restruct.py must ignore view macros (RET-VIEW, KR-VIEW), else it
  treats them as memory casts.
- With a prototype, three call shapes stop compiling and all need the view (or the definition fixed): short-read (fewer
  than the callee reads), short-unread (fewer than the definition's params, missing ones unread), over (more than the
  definition takes: `too many arguments`; 891 of 6,239 sites in T6's bucket, 711 guess_CallActorEventHandler).
- A `()` line in a shared header whose overlays' definitions spell a param differently has no one prototype text: ledger.
- Probe: func_8017E358 (ov_SC02_031 short call 0 of 1, `$a0` passed through), 10/10 objects identical.
- Batch A (T6.c2): the dominant failure of a `()` -> prototype sweep is `conflicting types` against another prototype of
  the same name in the same TU (often a DECL-ARITY lie, e.g. `extern s32 func_80161208(void);` vs `(void *a0)`): grep
  each TU first; such callees keep `()` (ledger) until the other prototype is fixed. Pointer params of asm-only callees
  can be found from cc1's "makes integer from pointer" warnings. Some over calls forward the caller's own `$a0` with no
  setup: cite the jal only. A first compile had 1,697 FAIL objects with cmp all identical: read the FAIL list.
