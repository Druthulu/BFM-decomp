# Return-type lies: one prototype, RET_AS marks the shipped caller's view

- Rule (3.44 T5, R123/R158): the one prototype of a callee is its definition's. Where the shipped caller read the return
  in another width/sign (census: `$v0` read unextended after a callee exiting `andi 0xff`, or `sll/sra 0x10` the
  definition does not do), the call is `RET_AS(T, fn, (params))(args)`; include/common.h: `((T (*)params)(fn))`.
- The cast keeps a direct `jal` (R_MIPS_26) under this gcc; proven per object by scratch compile vs HEAD (C0589, C0590).
- Ledger: config/ret_view_casts.tsv, one row per (callee, view) with cites (callee exit writer + one caller read);
  `sig_evidence --check` verifies cites/sites/def_file; type_census counts RET_AS as KEPT class RET-VIEW backed only by that file.
- Ladder per callee: decls -> definition's type; a differing object gets RET_AS(old view) at its value calls (discarded
  calls never needed it in 3.44: 0 of 1,504 sites); a `void` definition whose callers read `$v0` (RET-VOID-READ) is
  widened instead, with a `/* $v0 at exit: … */` comment so RET-NONE does not grow; unless widening turns many void
  decls into new lies (func_8012EF70) -> decl void + RET_AS.
- Asm-label alias prototypes (`CNAME(...) __asm__("SYM")`) are declarations of SYM: rewrite them too; tools map a RET_AS
  on CNAME to SYM. SHARED_FN binds define the bound name in the binding TU.
- What stays ledgered (lying_exceptions, SHARED-DECL-SPLIT): one declaration in a shared header for per-overlay
  definitions that disagree (func_80145CEC void in 7 of 141 overlays, func_80173544 s32 in 1) — no single type fits.
- Traps: a cc1 error can leave an identical stale .o — check the compile FAIL list, not cmp alone; a scratch script named
  like a stdlib module (dis.py) shadows it.
- Result 3.44 T5: DECL-RET 116 names -> 0 unledgered (8 SHARED-DECL-SPLIT rows), 25 view rows, 1,504 RET_AS sites, R22 218/218.
