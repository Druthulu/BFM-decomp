# Decode resident game text from splat .word data for `string` naming evidence

Problem: splat emits the resident's data tail as `.word` lines (asm/resident/data/tail.data.s), not `.asciz`, so a
function that returns or prints a game string shows only an address (C0570: short .asciz is no string either).

Move (3.43 T10.c1, .run/3.43/t10/txt.py, 18 lines): map every `/* off VRAM ROM */ .word 0xXXXXXXXX` line to
VRAM -> word; for a target address read words little-endian byte by byte, printable ASCII as is, others as `<xx>`,
stop at the first 0 after a letter. Text records start `02 00 00`; `01 02` / `01 01` are colour codes.

Use: a function selecting texts by state (func_80141CA4 picks story-goal lines by story progress) gets a `string`
evidence kind with the decoded line and its tail.data.s line as citation, e.g. guess_GetStoryGoalText
("Gotta collect all of the Five Scrolls ...", tail.data.s:70977). Still `guess_` unless the string names the function.
