# Rung T at fleet scale: global keys, shared-header bodies, missed declarations

Context: 3.45 T16.c8-c9 (4f72a4a357, 1eff0e2057, chunks 1745ef06c5..8a1ac1ba09: 964 keys, 192 typed, 0 walls).
- Header TU visibility (c8, 4f72a4a357): a shared body header (`src/shared/ov/*.h`, SHARED_FN) sees a type only when
  EVERY includer sees it; check all includers before retyping a param inside the body.
- Global-key cost (c9, 1eff0e2057): a global named in thousands of files (guess_g_PlayerActor: 3,797) cost ~87 s/key
  because the hook built a full file view per file and called `includers()` ~69x per key uncached. Fix: includers once
  per walk; prefilter a file by "no `)` or `CAST_` between the use's statement start and the use" before any full view;
  cache per-file cast-type sets. Now ~1.5 s/key (42-46 s for the first key of a new name). Re-plan of 210 ledgered
  keys gave identical verdicts: prove a speed fix by re-planning a ledgered slice.
- Trap: `signature_change` misses some declarations: md `extern` copies of a ret-of retype (DECL-RET, 9 lines) and
  per-instance declarations of a SHARED_FN body's param retype (DECL-PARAM, 16 lines). Run `sig_evidence.py --check -j 16`
  after every rung-T `--write`; hand-fix the named lines; scratch_cmp them (all identical).
- "conflicting types for func_X" on a SHARED_FN / shared-header param retype is a compile error, not DIFFERS: the engine
  makes no second attempt; it is ledgered pending (unwritten), not a wall.
- Pending mix at scale (964 keys): field holder/source untyped ~29%, 2+ cast types ~18%, arith/mixed kind ~14%,
  type not canonical ~4%. Typed rate ~20% per pass: holders and callees first raises it (C0623).
