# lwl/lwr in an asm data-flow: rt is a full write, not a read

- Architecturally `lwl`/`lwr` merge into rt, so a naive read set marks rt as read. The compiler emits them as a pair that overwrites rt whole (an unaligned 32-bit load), so for liveness and read-before-write questions treat rt as written, not read; rabbitizer reports it that way.
- Seen 3.44 T3.c1 (tools/sig_evidence.py): with rt counted as read, every `lwl $v1` after a `jal` looked like a 64-bit return read through $v1: 1,025 false ret64 classes. Fixed: ret64 0 fleet-wide; the selftest asserts the lwl register set.
- Same check for any register-set table: verify mfc2/cfc2 (write rt), mtc2/ctc2 (read rt), lwc2/swc2 (read only the base), mfhi/mflo, jalr (rd = $ra) against fixtures, never from memory.
