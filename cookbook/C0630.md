# Name an actor variant by its kind: trace the function to its actor-table entry

Context: 3.45 T17 judges c6-c7 (93 actor-slot views, 41 variants named).
- The owner of per-kind data is the KIND, i.e. the handler at entry N of the overlay's actor table (overlay header +0x60
  word; header +0x50 = 0x800D6118 anchors the header in the overlay data). Trace a function by its data word: the table
  that holds it, the C function that dispatches or installs that table, up to the header's +0x60 table. Kind numbers are NOT
  uniform across overlays (c11: entry 988 is func_80180450 in SC06_010 but guess_ShowEneLabelAndValue in SC03_014; entry
  507 differs between SC05_003 and SC05_005): merge variants across overlays only when the handler bodies are copies
  (same body / shared header), named after the lowest overlay's copy; otherwise name after the source's own overlay.
- Name the variant `k<ovl>_<handler addr>` and record kind N; never by a state function the handler dispatches to (T16
  did, so SC02_005 kind 61 carries 5+ names per gap and md_SC07_003 kind 802 two: merge them per gap).
- Owners hidden from a plain dispatch walk: event tables {code, fn} installed at actor +0xBC, callbacks at +0xDC; md module
  handlers appear only as raw address words in an overlay's actor table (md_SC02_009 = SC02_005 entries 88-89; md_SC07_003
  func_801A01D4 = SC07_002 entry 802), and their dispatchers cast a0 to the player type (a cast trap).
- Traps: a false data label can split a table (SC01_009 D_801A8004 inside D_801A7C20); some copies' tables have no data
  reference (judge by identical bodies); a kind may run past a gap edge (SC06_000 kind 617: child pointers +0xCC..+0xD8).
- Keep the tracer script with the judgments: c7 wrote one and did not keep it; a scripted trace made 47 types high-confidence.
