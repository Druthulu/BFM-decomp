# Where cross-type struct evidence lives in drafted matched C: casts and untyped slots, not typed flows

- Measured on BFM at 3.45 T2.c1 (tools/struct_twins.py --links): of call arguments from a struct-typed identifier
  into a placed callee, 15,313 enter a void/scalar parameter, 1,253 a parameter of the same type, 26 one of another
  type; member loads 194 same type, 25 cross. Cast views `((B *)a)->f` with a bound to A: 8,371.
- So typed-slot pointer flow finds almost nothing: drafting (m2c + band types per owner) already made each typed
  flow agree. Cross-overlay identity passes through untyped main parameters (`void *`, `s32`) that the callee then
  casts, and through shared main-resident globals (most accepted links: 1,974 of 1,987).
- A merge census must therefore read an untyped slot's effective type (the one struct type its callee casts it to)
  and decide explicitly about cast views; a typed-flow-only census under-merges by orders of magnitude.
