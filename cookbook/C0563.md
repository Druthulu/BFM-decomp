# A share batch lowers site counts without removing a site

**When.** Reading a drop in lever, cast or residue site counts in the same window as a share (dedup) batch.

**Mechanism.** `lever_census` and `type_census` count a site inside a `src/shared/**` header once (lever_census.py:839-869),
while a private copy counts once per copy. Moving a class with k private copies and s sites per copy into one header
lowers the count by (k-1) x s. Every binary still compiles the same construct, so the bytes do not change and the drop is
not a crack.

**Check.** `git diff <before>..HEAD -- src include | grep -E '^[-+][^-+].*<site pattern>'`: removed minus added lines is the
drop, and the added lines sit in `src/shared/**/cls_*.h` or `func_*.h`. Example 3.42: pins 974 -> 971, all from
cls_b0ef21e92162 (2 copies x 3 pins -> 1 header x 3 pins); residue rows 2 -> 1 (key SHARED_FN).

**Do.** Label such a milestone row as de-duplication, and never credit it to a delever or restruct rung. The prose for it is in docs/levers.md §7 (3.42).
