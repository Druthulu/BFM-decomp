# Asm-body families whose copies differ in one symbol: SHARED_SLOT via stringify

Context: hand-written asm bodies (scratchpad trampolines, PERMANENT in-function verbatim rows) with one copy per overlay; bytes differ per copy (134 h_exact over 141 binaries), so the census never groups them.

- Measure first: diff every copy token-wise (regex the defs, compare token lists). 3.42 T7: the callee was constant; the varying token was one data symbol (`%%hi/%%lo(D_X)`, 4 positions). Signatures also varied by binary.
- Header: `#ifndef SHARED_STR` 2-level stringify; body `"lui $at, %%hi(" SHARED_STR(SHARED_SLOT) ")\n"`; site = `#define SHARED_FN F` / `#define SHARED_SLOT D_x` / `#include` / `#undef` x2. SHARED_FN keeps share_census's param-include form.
- Signature: take the family majority; align minority binaries' `(void)` externs (plain `()` externs are compatible); byte-neutral when the body is all asm.
- Registry: one hash per h_exact group cannot hold 134 hashes and dedup_integrate needs >=2 members: use `tier: h_text`, members carry their own h_exact.
- Tools that parse asm templates must accept the macro between literals: tools/verbatim_check.py scan_in_function names a `SHARED_FN` header def by its file stem; tools/lever_census.py classify_asm_body accepts `SHARED_STR(x)` (SHARED_STR_PART) and run_census names a `SHARED_FN` asm-body in src/shared by file stem so the in-function PERMANENT row exempts it (else 20 UNATTRIBUTED, asm 899 vs 879).
- commit_task.sh refuses a git-rm'd path: pass its directory.
