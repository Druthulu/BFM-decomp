# Arity disagreements: widen the definition or the declarations, pins to params, residue keys

Context: 3.44 T8.c2/c3 (decl<def 34 names, callers-set 188 names, ARG-OVER 30 names); all byte-identical.

- decl<def with def >= census arity_lb: declarations take the definition's prototype; short calls become KR_AS + kr row (C0594).
  This also clears DECL-EMPTY-CONFLICT ledger rows (a wrong `(void)` prototype in the TU was what kept `()` lines).
- Callers set the declared count (census sites.min >= decl count): widen the definition with unread params (byte-neutral).
  Exception: a header-scale unit where widening would flip 600-3,700 agreeing `(void)` declarations while census sites
  show callers passing fewer: do the reverse (minority declarations to the definition, over calls KR_AS KR-OVER).
- ARG-OVER: a pin that stood for an argument becomes a parameter (C0508:2); an uninitialised local (switch with no default)
  allocated to $aN is no argument: ledger UNINIT-LOCAL with the read cite.
- A struct/union returned by value takes a hidden pointer in $a0: sig_evidence counts it as one word (ret_words, 3.44 T8.c3);
  tagless `typedef struct {...} Name;` must be recognised too (argcheck's typedef table misses them).
- Trap: the cast residue ledger keys a site on (form, `<bclass>:<base>`, off); turning a pin local into a parameter changes
  bclass local->param, so its RESIDUAL/KEPT rows stop matching (uncovered P). Fix in C: use an existing struct field
  (`((Unkstruct_X *)a0)->unk20`) or retype the param, not by re-keying. Finders: .run/3.44/t8/c3/unc.py, unb.py.
- Trap: type_census prints the total unbacked count on the KR_AS line; the site may be another macro class (CAST_SIGN).
- Trap: gcc reports a conflicting definition at its `{` line, not the head line.
