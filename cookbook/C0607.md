# Hub guards for struct-merge evidence: key slots by routine copies, test types, route body links through them

- A per-slot hub test (a parameter that receives >= K types, or whose types conflict) misses generic helpers that
  are copied into every overlay: each copy is its own slot with 1-3 types. 3.45 T2.c3: a 112-type star on
  Unkstruct_800B5CB8 (the struct map's known `suspect` merge) formed from 93 eff-flow links through such copies.
- Key the slot by the routine's byte identity (h_exact class, parameter i) so its copies are one slot
  (T2.c4: param/h194bedddb279974f/0 merged 47 copies, 14 types, a width conflict at 0x18).
- Test types too: a type whose pointer-flow partners number >= K and include a conflicting pair is a header or
  conduit type; refuse its pointer links (T2.c4: 800B5CB8 93 partners, 80126B58 13).
- Body links (the same slot spelled A and B in copies of one routine) are evidence only when the routine is not a
  generic helper: route them through the same slot test, and never let two hub types merge on any link (T2 expert:
  after the 0x18 conflict left, body-view copies joined 800B5CB8 and 80126B58 into one 10-type component).
- Order matters: each refusal removes a conflict that was blocking another merge. Re-read the largest components
  after every guard change.
- Implemented in tools/struct_twins.py --links (hkey, bkey, the hub-type block).
