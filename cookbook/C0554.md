# Ghidra live-DB type import, and calling the MCP without MCP tools

## Import type rows into the live project (not the rebuild scratch)
- Preconditions: `ss -tln | grep 8080` empty and no `AnalyzeHeadless` (a read or write open needs the project lock). Never stop a Ghidra this task did not start.
- Back up `ghidra/` first (`cp -a ghidra .run/<phase>/<task>/ghidra.bak`, ~1 GB).
- Import file = the committed `config/ghidra/<p>.jsonl` `program` row + `config/ghidra/types/<p>.jsonl`. The program row makes ImportAnnotations refuse a wrong image base or language. Do not import the full `ghidra_types.py merge` output into the live DB: it re-applies the committed func/comment rows over live edits.
- `analyzeHeadless ghidra bfm -process <p> -noanalysis -scriptPath tools/ghidra_scripts -postScript ImportAnnotations.java <abs file>`; require rc 0 and `BFMANN .*failed=0 `.
- Prove that it persisted: `tools/ghidra_export_annotations.sh --out <dir> <progs>`, then `grep '"path":"/bfm/'` the type rows and `cmp` them against the types file (byte-identical when correct; ExportAnnotations uses the same row form).
- Then `tools/ghidra_mcp_start.sh`, wait for `serving` in `.run/ghidra-mcp.log`, and the developer runs `/mcp`.

## A subagent without `mcp__ghidra__*` tools can still call the server
- `.mcp.json`: SSE at `http://127.0.0.1:8080/sse`. GET `/sse` returns an `endpoint` event; POST JSON-RPC to it (`initialize`, `notifications/initialized`, `tools/list`, `tools/call`); each reply arrives as an SSE `data:` line with the matching id.
- Script: a stdlib urllib reader thread plus a queue, ~40 lines. Struct lookup: `tools/call types {"action":"get","name":<n>,"program_name":"SLUS_007.26"}`; `get_binary_info {"program_name":...}`.
