# Fold engine walker misses and spurious unions on value-shape folds (P3.45 T7.c14)

- restruct --fold-row/--fold-batch respells member accesses by offset only where the base's type is visible to its walker.
  It misses: accesses through a struct FIELD typed with the member (`s->pt[i].vx`, `fr.v[3].z`), macro-parameter bases
  (`#define RW32(p) (((T *)(p))->v)`), macro-aliased globals (`#define RES_FILE aResourceIdMap`). Small shapes (SVECTOR-like)
  sit inside many records, so value batches hit thousands of misses (b6: 14,313 sites in 165 files).
  Workaround used: field maps from the plan (.run/3.45/t7/c14/plan_maps.py) → build → grep "has no member named" →
  respell by map (fixnm.py). The real fix is in the walker.
- scratch_cmp reports a compile failure as `FAIL new` with no compiler text, so a gate that greps its log for
  "has no member named" never fires: gate on the FAIL count, then `make -k` the failing objects for the text.
- Merged definitions grew spurious named unions for variants that are one type: `short` vs `s16`, field lists differing
  only by padding, array vs scalar spellings of the same leaves (union variant structs 36 → 54 in five batches).
- PsyQ targets are refused when a member spells the shape as an array accessed by a variable index (`d[i]` cannot map
  onto CVECTOR's r,g,b,cd): split the array-shaped members to their own target, citing the variable-index access.
- 5 batches of ~50 class parts: --write 7-10 min each; the full gate chain ~35 min per batch.
