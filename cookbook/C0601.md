# Prove a C-vs-bytes gate bites in a scratch worktree with no rebuild
A check that reads C sources plus build products (.d files, linked ELFs, a census) can be fault-injected without
rebuilding:
- `git worktree add .run/<phase>/<task>/wt HEAD`; symlink `tools/reference`, `.venv`, `asm`, `assets` and `extracted`
  (the worktree's tracked `extracted/` holds only a manifest: replace the dir with the symlink).
- `wt/build` = a real dir of symlinks to every entry of the main `build/`, EXCEPT the tool's own output dir, which is a
  real dir seeded with a copy of its input (e.g. `build/sig_evidence/census.jsonl`), so the main tree's outputs are
  never overwritten. The .d files name `src/...` relative paths, so the worktree's edited sources are the ones parsed.
- Run the worktree's copy from inside it: baseline rc 0; one injected fault (a declaration's return type, one
  instruction in a ledger cite) -> rc 1 with exactly that count; revert -> rc 0. Then `git worktree remove --force`, prune.
- The read-guard hook blocks `sed -i` on files over 20k chars even in the worktree: use Read by range plus Edit.
