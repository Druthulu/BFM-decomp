# Cite a curated name to its PsyQ library object (and SDK names we compiled from C)

When: a names-ledger row must cite a name the build takes from Sony's SDK (evidence kind `library symbol`, rule 1).

Linked objects (build/psyq/<dir>/<OBJ>.o):
- Object + offset from the link map (`leverage_rank.parse_map`, interval lookup by vram); section offset = addr - section start.
- Object's own symbol at that offset: `mipsel-linux-gnu-nm` on the .o (locals included); a different name there -> `conflict`.
- SDK origin: the archive member the .o came from (tools/psyq/lib40_elf/*.a; libapi 4.2 and libpad 4.2.1 from lib421). snd = LIBSND+LIBSPU mixed, apicard = LIBAPI 4.2+LIBCARD: resolve per object, never per dir.
- bss-split objects (libgpu SYS, libgs GS_001, snd VM_F) are not .text-identical to their archive member: match .text with every relocated word masked.
- A game name the map puts inside an SDK object's .bss (lzss_sectorStagingBuf in VM_F .bss) is a game name: cite its own evidence, put the map placement in `conflict`.

SDK functions compiled from our C (no linked object): compare the SDK member's .text to the built binary's bytes over the function size, relocated fields masked; run a wrong-address control (must be unequal). Record each result as a docs/memory-map.md row and cite that line.
- psyq-obj-parser fails on LIBSN SNMAIN.OBJ (`Unsupported relocation expression type: 22`): read .text from the raw LNK code record and relocations from the parser's `-d` listing.
- LIBDS is not in lib40_elf: split and parse LIBDS.LIB like tools/psyq_build_libs.sh does.

Scripts (3.43 T5, scratch): .run/3.43/t5/cite_rows.py, sdk_compare.py.
