# Width evidence for cast-only struct types comes from their cast-view accesses

- In drafted matched C most placeholder types are never bound to an identifier: they appear only as
  `((T *)x)->f` on an untyped x (3.45 T2: 2,639 of 4,112). A width map fed by bound-identifier accesses alone sees
  none of their fields (Unkstruct_80126B58: 1 accessed field of 203), so merges of such types pass every veto.
- Count each cast-view member access as an access of T's member (offset, width, sign from T's layout; sign only on
  loads of <= 2 bytes) and, when x is a parameter (or its single-source local), as that routine's own offset.
  3.45 T2.c5: width-map types 669 -> 3,803; hub slots 33 -> 254 (248 by width conflict); 80126B58 121 accessed fields.
- Keep "own objects" (what makes a type `apart`) on bound accesses only, or every cast-only type looks evidenced.
- Each new veto reshapes the components (refusals remove the conflicts that blocked other merges): re-read the
  largest components after the change (T2.c5: a 53-type component re-formed on the map's `suspect` 800B5CB8).
