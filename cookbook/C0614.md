# A dense value-shape test must not let pad fields cover the size

Problem: classing exact layout twins into "dense small value shapes" (leaves from offset 0 cover the size, <= 32 B) with
struct_twins.sources_projection's `dense` test counts every leaf, pads included. A placement view such as
`struct { u8 pad0[0x12]; u16 unk12; }` then reads as the shape `u8[18]+u16` and dozens of unrelated one-field fragment
views look like one value type (P3.45 T7.c1: 154 value classes / 1,201 removable, most of them pad-led views).

Fix (P3.45 T7 expert, .run/3.45/t7/c1/groups.py dense_np): find each PAD_RX (`padN`) field's leaves by laying out the
field-list prefixes; drop pad leaves except those after the last non-pad leaf (SVECTOR's trailing pad slot still covers);
a class is a value shape when a majority of its members pass (one all-pad blob member must not veto the class).
Result at c54ca2f5cc: value 55 classes / 682 members / 627 removable; twin 252 / 783 / 531; sparse 167 (tracing).
The pad-led views go to tracing (absorption), where their offset is the evidence.
