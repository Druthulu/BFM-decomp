# A data rename breaks tools that classify by placeholder spelling (D_/func_ prefix)

**Wall (3.43 T7.c2).** R22 stayed 218/218 and every rename scan was green, but tools-health failed: `type_census.py
--check-casts --residue` reported 1,979 uncovered cast sites (P46 I1256 M677) after 10 data globals were renamed.
Two mechanisms:
1. type_census classifies a cast base as `global`/`gaddr` only when it starts with `D_` and as `func` only when it
   starts with `func_` (type_census.py:248-261, :324-326); a struct's address comes from `D_` in a name (:943). A renamed
   `g_X`/`guess_g_X` becomes `ident`/`addr-of`, so residue keys `<bclass>:<base>` no longer match, and struct-map's
   unassigned sites jump (3,298 -> 4,405).
2. rename_sym.restruct_ledger (rename_sym.py:311-327) rewrites only `fn` in .run/P37/restruct/ledger.jsonl; `unit` (the
   ledger_latest key) and `sites[].base` keep the old name.
Also name-blind: delever.py:3129's R26 detector matches only `&(D|g)_<8 hex>`.

**Invariant to test.** A rename is census-neutral as well as byte-neutral: the type census, the residue coverage and the
lever counts at the batch commit equal those before it, modulo the names. Check that before a batch lands, not after;
`rename_scan` and R22 cannot see it.

**Speed (same run).** rename_sym deduplicated by (old, new): dry run 17m28s -> 52s, byte-identical. rename_scan parse_spec
kept distinct renames: 9m57s -> 24s. A full `--spec` scan of an 82-row batch still takes ~85 min (git grep over address
patterns): run it in the background.

**Fix that held (T7.c3, 2e0afe4e05).** A rename->placeholder map built from config/names.tsv rows whose history starts
with `D_80`/`func_80` (curated `seed:` names excluded, so legacy classes stay put), read by lever_census
`placeholder()`/`placeholder_text()`/`NORM_SYM` (and in TOOL_STAMP) and by every type_census spelling test, PLUS the
places that read names without a prefix test: struct naming order/address, hash-derived type names, union-find root
order, `shared_fn_header` keyed by name (header files keep placeholder file names). Spelling tests alone left 8 cluster
diffs. rename_sym `ledger_row_rename` rewrites fn, unit, callee, real and sites[]/bases[] base. Proof: worktree census at
the pre-batch commit vs after, names mapped back: types 14376/14376, unassigned 3298/3298, residue 0, lying 9302/9302.
Open: delever.py:3129 R26 still spelling-keyed (uncounted); ledger rewrite keyed by old name alone.

**asm-label aliases (3.43 T9.c11-c13, d3a8dcdc00).** A definition bound by `__asm__("<label>")` keeps its renamed
label as spelled in share_census alias_decls: the restruct ledger is keyed by the emitted name, so mapping a renamed
label back to its placeholder (5349ee329b, superseded) left 7 P sites uncovered (TYPE-CANON-TWIN 3591 -> 3584).
Also: progress.py pairs the newest series census (.run/P39/census) with current ledgers; after renames its
published numbers drift (unbacked 26 -> 29) until that census is refreshed (d1-snapshot skill) before tools-health.
