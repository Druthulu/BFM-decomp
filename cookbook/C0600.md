Context: 3.44 T8.c5: 13 library names / 10,040 declaration lines brought to the PsyQ 4.0 header prototypes, 0 bytes moved.

- Source: tools/reference/psyq-sdk/PSX/INCLUDE/ (Library 4.0 CD); its PSX/LIB/*.LIB are md5-identical to tools/psyq/lib40,
  the libraries main links (C0015). Take the return type and arity from the header; keep project parameter spellings where
  the arity already matched (callers pass (s32) casts; pointer params would clash with other declarations in a TU).
- Library names have IMPORTED sig rows and no census class: sig_evidence never compares them; a scratch measurer does
  (.run/3.44/t8/c5/measure.py, reusing the comment-masked balanced-paren parse).
- The headers are Shift-JIS with CRLF: `grep` without `-a` silently skips LIBGTE.H, LIBCD.H, LIBSPU.H, KERNEL.H.
- A new typedef in include/struct_types.h (e.g. DISPENV) needs offset-named pad fields (check-structs pad_names) and
  `tools/ghidra_types.py --write` (ghidra_types --check STALE); tools-health shows the second only after the first is fixed.
- Scratch recompile trap: a relative `-o` path makes the assembler fail and leaves the old .o, so cmp compares stale bytes;
  use an absolute output dir and read the FAIL list (C0589).
