# Cross-image calls: a module's splat symbol stack omits the overlay beside it; resolve outside-stack targets by function start

- A splat yaml's `symbol_addrs_path` is a naming stack, not the load set. Modules (md_*) stack main + own (resident deliberately omitted when the module loads inside resident's window), and never the overlay loaded alongside, yet they `jal` into overlay space and store overlay function addresses.
- A call-graph or liveness census that resolves `jal` targets only through the stack drops those sites: 3.44 T3.c1 lost 392 targets, so callees looked `no callers` and 6,519 `unused` instances were unsound (func_801633A8, func_80188F10 in config/lying_exceptions.tsv).
- Fix (tools/sig_evidence.py rule OUTSIDE-STACK, docs/ops/sig-evidence.md): a target outside every stack image resolves fleet-wide by function start: exactly one h_exact class starting there is credited; two or more give each `cross-binary target unresolved`; none is only counted. Address constants outside the stack mark every binary with a function starting there as address-taken.
- Control that caught it: check each known return-lie callee for at least one caller read; a ledgered callee with no callers is a resolution bug.
