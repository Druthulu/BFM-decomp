# Typing a tagged/masked pointer byte-identically; hand-insert new ledger rows

Context: P3.45 T17.c29: S5 (actor unk90 typed `Unkstruct_80185680_2 *`) made func_80181824 (ov_SC03_030) local `p`
typeable; its record at (unk90[i].unk0 & 0xfeffffff) + 0x50 became `Rec_80181824` (8 bytes; survivor, member).

- One cast expression `p = (Rec *)((tag & 0xfeffffff) + 0x50);` moved bytes: GCC folded the +0x50 into every load
  offset. Matching form: do the mask and the add in place on the integer, then copy it once:
  `tag &= 0xfeffffff; tag += 0x50; p = (Rec *)tag;` (asm identical). A plain `(T *)int` conversion is not a census form.
- Reading the bytes through members instead of `*(u32 *)p`, `*(s8 *)(p + 3)` removed the casts that S5 would have made
  typeable (casts_I would have risen by 1 and failed the ratchet, C0641).
- `struct_twins.py --dispositions` rewrites every row's file_line (about 2,370 stale lines at the time): to add one row
  (a new survivor), insert it by hand in key order and run `--dispositions --check`.
- `git apply --3way` of an old .run patch fails once the patch's blobs are gone; plain `git apply` per file, then
  hand-apply the header hunk, worked for 1,286 of 1,287 files.
