# A lexical binder must let a function's own parameters shadow file-scope bindings

- A file-scope declaration can introduce parameter-like names: `extern void (*D_8017F0D8[])(struct S80131E00 *a0);`
  (ov_SC01_000_o0c.c:524) names `a0` inside a function-pointer prototype. A binder that falls back to file scope for
  an unbound identifier then binds every untyped `a0` parameter in the file to S80131E00.
- 3.45 T2.c2 (tools/struct_twins.py bind_of): fixing it moved refused views 8,371 -> 461, callee unplaced instances
  4,712 -> 1,678, same-type arg flows 1,253 -> 315. One bad binding fanned out over every m2c-named parameter.
- Rule: resolve an identifier innermost first (block locals, the function's own parameters, then file scope), and
  never take names from inside a prototype's parameter list as file-scope bindings.
- Check: spot-read cited lines of a sample of links before trusting any count (this bug was found that way).
