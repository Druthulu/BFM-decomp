# restruct --fold-batch: one tree per batch of folds, and the traps it fixed (P3.45 T7.c11)

- `PY tools/restruct.py --fold-batch FILE [--write]` (a1c79af0c6): one component per line (comma-joined keys), applied in
  sequence on one tree; checks src/include/config clean once at start; skips and lists refused or crashing components;
  rewrites the restruct ledger once. Cost: 425-581 s for 24-27 components; one 1,505-file component (C3) 613 s; a dry run
  of 36 components 1,274 s. Gate the batch once (scratch_cmp --rev <base>), commit, `--fold-stamp`, commit.
- Sign conflict at one offset (same width) → named union per sign `union { s16 s; u16 u; } f6;` (cc1 rejects anonymous).
- Merged definition placed at the earliest definition in include order (struct_types.h before engine_types.h); refused if
  one of its field types is defined after that point (C13 broke every object before 9a2b90a8f9).
- Walker gaps that broke compiles (7813260d17): `*(T **)&x` bases; a function- or file-scope `extern` of another type
  shadows the header global (144 objects failed before).
- Census order after a fold that changes a twin class: census → `struct_twins --write` → census again (green only then).
- A fold can make two overlay bodies normalize to the same text, creating a new share/dup class (C32): fold their argument
  types too (body evidence) or the census gates.
