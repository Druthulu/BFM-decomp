# C0612 — Fleet-wide struct fold traps: asm-label declarators, no anonymous unions in cc1, absorb +off needs source rebase

# A fleet-wide struct fold: the traps behind "has no member named"

**Context (3.45 T6.c2).** `restruct.py --fold-row KEY [--write]` retypes a member struct M to a target T in every file. It
respells M's member accesses by their offsets, using the rung-HF helpers `_typed_vars`, `_lvl` and `_hf_file_edits`.

**Traps the byte judge caught. Run scratch_cmp on every touched file before R22.**
- **Declarators with an asm label.** In `extern M D_x[] __asm__("D_80…");` the declarator ends in `__asm__`, not `;` or `=`.
  The type-aware walker missed these bases, so their accesses kept M's field names. The result was 8 objects that failed
  with "has no member named f4". Fix: `HF_ASM_LABEL` in `_typed_vars`, plus a selftest.
- **No anonymous unions.** The PSX cc1 rejects anonymous unions inside a struct (probed: "structure has no member named").
  A width or sign conflict inside a fold target becomes a NAMED union: `union { struct {…} v0; struct {…} v1; } unk<HEX>;`.
- **Absorbing at an offset other than 0.** It cannot be done by rewriting tokens. The view's pointers address parent+off, so
  retyping them to the parent means rebasing every source. That is the typing engine's work. The fold engine prints the
  merged definition and refuses. 485 of the 505 flow candidates in T14 sit at offset 0.
- **Spelling-keyed stores.** type_folds.tsv, tnc_band.tsv and dedup_exceptions.tsv get a token rewrite. In the restruct
  ledger (`.run/P37/restruct/ledger.jsonl`, 542 MB, untracked) rows are rewritten in place, the way
  `rename_sym.restruct_ledger` does it. Ledger keys of the form `Name@file:line` are rekeyed through a line map (C0572).

**Proof.** The 3.45 T6 P1 fold covered 138 files and 2,011 edits. scratch_cmp 4284/4284 identical; R22 218/218; census
controls 4/4; residue uncovered 0.
