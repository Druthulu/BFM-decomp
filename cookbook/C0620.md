# Layout hash and census twin rules after the 3.45 folds (P3.45 T7.c17)

- struct_layout.layout_hash ignored bit-field widths: {a:16,b:16} and {addr:24,len:8} hashed as one exact twin class, so
  a fold could merge different bit layouts. Since c6fd6c2975 a bit-field leaf is `(unit_off, w, "bf<off>:<bits>")`
  (sign still ignored); 9 hashes changed; ledger `lhash:` evidence of affected rows must be rewritten with them.
- Census tier-1 rows (a meaningful signature plus opaque names) gated even when the opaque members were kept apart on a
  cited conflict and wait for tracing. Now a tier-1 row listed in docs/struct-twins.md `## Twins` passes when every
  definition in it is a pending ledger row (apart/no-evidence) except at most one unledgered canonical/PsyQ type;
  type_census exports `structs_tier1_listable`, struct_twins reads it (one rule, one place).
- Folding out the last meaningfully-named member of a class flips the rest to tier 1 (C0619): with this rule, list it.
- Merge: `void *` and a one-level typed pointer at one offset are one type (typed wins); a variant whose scalars map onto
  the host variant's fields by constant path joins it; `--fold-collapse` can write a union with fewer variants.
