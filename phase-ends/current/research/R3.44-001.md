## Answer
1. Args: $a0-$a3 (mips.h:1881-1882, MAX_ARGS_IN_REGISTERS 4 at mips.h:1886). Home area 16 bytes: REG_PARM_STACK_SPACE = 16 - FIRST_PARM_OFFSET(0) (mips.h:1820-1821, 1809), caller-owned (mips.h:1828 empty OUTGOING_REG_PARM_STACK_SPACE). Arg5+ on stack: function_arg returns 0 when arg_words>=4 (mips.c:2931-2937), so arg i>=4 sits at entry-$sp+16+4*(i-4) (inferred from the 16-byte home area). DImode and double: arg_words rounded to even (mips.c:2890-2891, 2925-2928), so a64 starts at a0:a1 or a2:a3. Varargs: callee spills $a0-$a3 to the home area when the prototype ends in ellipsis (mips.c:4996-5017; offset tsize-dependent, 5008-5010).
2. PROMOTE_PROTOTYPES (mips.h:1153). Caller: c-typeck.c:1740-1744 widens char/short args to int with default_conversion, so signedness follows the C type (lb/lbu, lh/lhu, or sll+sra/andi after a load). Callee: no PROMOTE_PROTOTYPES consumer in function.c. The promote_mode sites (function.c:3326, 3970) are gated by PROMOTE_FUNCTION_ARGS, which mips.h does not define. So the callee does not re-extend at entry (inferred from absence). Callee-side narrow use shows as sll/sra or andi at the use site, or lb/lbu when reloaded from the home slot.
3. PROMOTE_FUNCTION_RETURN: NOT defined for MIPS (only function.c:5095, calls.c:2116, stmt.c:2517 reference it; none in mips.h). No callee re-extension on return and no caller extension after jal. Any andi/sll/sra after jal comes from C-level conversion in the caller, which is the 3.41 u8/short mismatch pattern.
4. STRUCT_VALUE 0 (mips.h:1318): hidden address is an extra first argument (calls.c:919-921), so it takes $a0 and visible args shift by one. RETURN_IN_MEMORY is BLKmode only (mips.h:1937-1938). But aggregate_value_p returns 1 for every aggregate when flag_pcc_struct_return (function.c:3130-3133). DEFAULT_PCC_STRUCT_RETURN=1 (toplev.c:328-329, 334), not overridden in mips.h, and the Makefile has no -freg-struct-return. So struct/union returns go through memory with $a0 as the pointer. Pointer in $v0 on return: unknown (not read). 64-bit return: LIBCALL_VALUE gives GP_RETURN=$v0 (mips.h:1876, 1891-1897); 32-bit DImode spans two words (mips.h:1255-1257), so $v0:$v1 (inferred).
5. Soft float: Makefile:1044 CC1FLAGS := -quiet -O2 -G0 -mips1 -mcpu=3000 -mgas -msoft-float -fgnu-linker (-O0 variants at Makefile:920, 1082, 1111, 1119). FP args go in GP regs (mips.c:2874, 2886, 2893-2898); FP_RETURN = GP_RETURN under soft float (mips.h:1877). No -mgpopt in CC1FLAGS (gp-relative disabled by -G0, not read in mips.c). -O0 objects have fp-based frames (Makefile:1078-1079), which changes slot offsets.
6. f();-void vs f();-int vs return f(): NOT verified. expand_call/expand_return were not read in full. Only calls.c:2116 and stmt.c:2517 are seen, and both are inactive for MIPS. A jal alone cannot distinguish void from int. Use of $v0 after jal is the only evidence. Tail `return f();` is unknown.
Planner rule: record arg count from the a0-a3 reads and the 16(sp)+ reads, width/sign from the caller's lb/lbu/sll-sra before jal, and return-used only if $v0 is read before a redefinition. Mark unknown for void-vs-int and tail-call cases.
DImode split quirk: function_arg_partial_nregs returns 1 for DImode at arg_words==3 (mips.c:3017-3023), but function_arg rounds to 4 and sends it to stack (mips.c:2925-2931). The two disagree. Asm must decide; mark "unknown" if a3 holds the low word.

## Findings
- mips.c:2850-2944 function_arg is the single source of register/stack placement.
- mips.c:2989-3024 function_arg_partial_nregs disagrees with function_arg for DImode at odd arg_words (see item 6).
- R54 void->s32 change (C0547) is consistent with item 6: the discarded call's return use is not visible to the asm.
