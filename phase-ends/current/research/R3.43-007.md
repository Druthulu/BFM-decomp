## Answer

(a) Plain-English story: In 3.43 we set out to give names to the 500 unnamed functions and data on a frozen worklist. The rename tools had gaps. They rewrote a placeholder name in every file, even where the same placeholder meant a different function in another overlay, and the leftover-name scan hung. Over 10 to 12 November the work fixed the tools first, then cited a name only where a recorded source existed (1,083 inherited names got sources; 2 had none and were demoted to guesses). Then the worklist was named in batches: 393 best guesses, 105 left unnamed on purpose, 2 cited. Every unsourced name carries the guess_ prefix. The phase also replaced 38 fake void-to-s32 returns with real returns or documented comments, and mirrored the names into the live Ghidra project.

(b1) Believed vs true:
- Believed 3.41 found the void-to-s32 problem (37 functions). The HEAD scan found 394 names / 9,009 definitions; 3.43 fixed only the 38 flipped by 3.41 and parked 356 for Gen 4.
- Believed a placeholder rename was a safe whole-repo rewrite. Placeholders are per binary; a repo-wide rewrite would rename unrelated same-address functions (T7 dropped rank 3 for this).
- Believed the worklist had evidence. 448 of 500 units had only their own code as evidence; 2 were live-verified.
- Believed the inherited names were sourced. Two (padState_raw, zoneLoadedBlock) were cheat-lore only and were demoted (T5).
- Believed 9 expand-hardreg-var wall tags were right. 5 of 9 were re-tagged (T4).

(b2) What failed and why it looked right:
- The rename tool's whole-repo token rewrite looked right because placeholders read as unique names. They are per binary (T7, T9).
- rename_scan hung for 11 hours on the first batch. Single-pattern git grep was fast, so multi-pattern use looked safe; git 2.43 falls back to line-by-line matching per pattern (96 patterns over 669 MB never finished) (T9).
- Census neutrality looked proven by equal counts, but the census classified by D_/func_ spelling and broke on renamed data (T7, C0572).
- T2 found class renames on most registry groups silently did nothing, and share headers were skipped as generated (would have broken the build). Both looked like working tools.
- T3's first scan missed 2 of the 38 (bare `return;`, K&R def). The scan also ignores comments, so the 19 commented defs still count as open.
- T4's 3.40 probe had a self-copy canonicaliser bug that produced a phantom diff and flipped two tags (T4).

(b3) What it cost:
- Dates (router rows, not work-time): T2 to T7 done and T7 review approved 2026-11-10; T8 done 2026-11-11; T9 to T14 done 2026-11-12.
- Hours and gate timings: T9 hang ran 11 h before a stop; a full 82-row rename_scan took about 85 min (T7); per ~30-row data batch: census 6.5 min, regenerate 7 min, R22 5 min, spec scan 20 to 30 min (T8); after the T9 fix, a 48-rename scan took about 7 s. Tool runs of tools-health and 21 Ghidra re-opens each exceeded the 285 s tool limit (T13, T14).
- Commits: no total in the summaries; per-task hashes are listed in each file.
- Coder runs (pa-coder, T2 to T12): 38 total: T2 1, T3 1, T5 2, T6 1, T7 3, T8 6, T9 14, T10 5, T11 3, T12 2. T4, T13, T14 had none. Losses: T8 c4 lost to a session restart; T9 c2 blocked (hang), c3 and c12 cut off by restarts; T9 c4, c5, c7, c8, c9 returned questions.
