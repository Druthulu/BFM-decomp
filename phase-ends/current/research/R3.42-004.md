## Answer
A body moved from a private .c into src/shared/**/*.h is a new TU-key for every keyed gate. Nothing in the census is keyed by SHARED_FN; all keys are file path (tu) plus function name, so a move changes the key.
- lever_census: the moved site is an unmatched --strict failure (its tu is now the header path) AND the old residue row (file = the .c) becomes residue-unused, which makes `--check --strict --residue` FAIL. Fix: rewrite the residue row's file column to the header path (or regenerate with --write-residue).
- type_census --check-casts --residue: per-site RESIDUAL(<cause>) lives in the restruct ledger (.run ledger.jsonl), not in source. Body key is (tu, fn). A moved body has a new tu, so its sites are uncovered; restruct --rung S --residue --restamp re-ledgers them under the header tu.
- type_census --check: lying rows are keyed (callee, defined_in, kind) against config/lying_exceptions.tsv (callee, def_file, kind). A moved defining body changes defined_in, so a ledgered lie becomes "unledgered lying" and FAILS.
- verbatim_check --strict: manifest keyed (binary, fn) with a stored path. A file-scope verbatim body moved to src/shared gets binary 'shared' and a new path, so it reports NEW plus GONE (or MOVED) and --strict exits 1. In-function rows keyed binary 'ov_*' are wildcard-covered and survive a move.
- Other path-keyed gates (lever walls, dedup_exceptions via share_census --check): see Findings 5. Not verified in full.
