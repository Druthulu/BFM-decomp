## Rationale
- Types before levers: rung S re-sweeps respell thousands of bodies; lever cracks after that run on the final body text, so no crack is redone. Types may also explain pins (the 3.39 premise).
- The canonical-types campaign is mechanical and tool-driven (write-types, rung S, residue rewrite), comparable to 3.39 T3+T4. It was pilot-gated: T2 measured conversion rate, header fan-out cost and new causes on the top 75 types (50% of TNC). Its projection showed TNC 0 does not fit (about 12.7k hand decisions for a 7k-site, one-site-per-type tail), and the developer chose the 95 % band (REPLAN 2026-10-15). T3 therefore builds the decision step as a tool (the T2 policy, mechanised) rather than deciding 6,676 rows by hand, and freezes the band so the tail cannot grow by re-ranking.
- Why a frozen list and not a site threshold: the milestone names the 95 % band (6,676 types); a threshold (e.g. ≤ 2 sites) would cut at a different count. Freezing by a fixed sort with a name tie-break is deterministic. Its weakness is hash-name drift (T2 gotcha): a band type renamed by a later census would fall into the tail. Hence the cap: TYPE-BELOW-BAND sites never exceed the tail frozen with the band, and T3 proves the names stable across a census re-run.
- T3/T4/T5 keep their split (headers, then ov sweep, then the rest): restamping before a sweep would stamp band sites with a pre-sweep cause (NO-EDIT), so tail and NO-EDIT restamps run per segment after its sweep. T3 also adds the zero-work exit to restruct_cycle.sh, since the T2 cycle re-drew the same files with 0 conversions (rS4..rS21) and both sweeps depend on it.
- T15 (ledger backup, queued by Claude 2026-10-14, carried by the REPLAN) runs after T13 so it backs up the final ledgers; T14 waits for it so the phase-close docs can name the step.
- The literal lever 0 is agent-priced. About 800 crack targets remain after the cheap tools ran dry (3.39 T8: 0 pins removed by delever R/E/G). The comparable legacy P36 lane took 9 sessions and about 15-20M tokens. The plan goes class by class, cheapest real fix first:
  - T8: re-judge 1,013 not-judged/author-left rows with the oracle; the GTE, asm-macro and asm-body classes;
  - T7: missing-parameter pins become declared parameters, a signature fix through rung D, as with 3.39 T6 lying decls;
  - T9: head-class cracks, where one crack propagates to every copy;
  - T10: a singleton pilot that measures crack rate and cost;
  - T11: the singleton wave at the developer's cap.
  T10 is the checkpoint: if its projection exceeds the cap, it returns `blocked` with numbers and Claude puts the milestone to the developer (see Developer decides). It did (REPLAN 2026-10-17); the developer chose the full wave with walled survivors.
- The wall rule (REPLAN 2026-10-17). A wall is a named compiler behaviour that plain C cannot steer around, with the pass that does it. Why a closed vocabulary file (`config/lever_walls.tsv`) and a tag in the cause column, not free prose: the tool can then check every row mechanically (unwalled 0, unknown tag 0), new walls need a vocabulary row with a pass and an evidence pointer, and a class label (`singleton(pin)`) can never pass for a wall. Why append ` wall:<tag>` to the existing cause rather than add a seventh column: `parse_residue` pads and drops columns silently (lever_census.py:1117-1126), and `residue_text` keeps existing rows verbatim (:1187-1195), so a column change would touch every reader for no gain. The rule runs whenever `--strict --residue` is given, so the milestone command is the one T6-T10 already ran; residue-unused, today printed but not in rc (:1392, :1395-1398), joins rc in the same change.
- Task split after T11. T18 (cast-gate leftovers) is the small fix REPLAN item 4 asked for. T19 builds the rule and normalises T11's wall strings onto the vocabulary; T20 walls the rows no wave re-judges (20 head classes, the T7 scratch pins, the two asm rows). T20 is needed because the amended milestone covers every site, and none of those 864 rows names a wall today (R3.40-011). T13 then checks the rule; it no longer runs the literal `--strict`.

Also which canonical name and file each type gets. Bytes cannot arbitrate type identity. 1 high task in 15 (T2, done); T3 applies T2's policy mechanically, so it is medium.

## Risks
- The TNC count may partly be stale cause stamps (the 80126B58 anomaly): then TNC falls by a ledger rewrite with no respell, which is not a real fix. T1/T2 must separate the two, and the record counts MEMBER/KEPT conversions, not only the by-cause drop. The same holds for the tail: TYPE-BELOW-BAND is a renamed residual, not a fix, and the record states it as such.
- Writing about 4.5k band defs (T2's define rate 68 % of 6,676) may conflict with `type_census --check-structs` 0 dup defs / 0 dead names (twins, defs rung S never draws). The T2 policy (TYPE-NO-MEMBER prune) must keep both at 0 at T5's end.
- Hash-name drift: band and fold rows key on cluster hashes, which can change when the census sees new bodies or new canonical types. A drifted band type would read TNC (failing the gate) or, if mis-keyed, inflate TYPE-BELOW-BAND. T3 re-resolves the names after every header batch; T5 and T13 cap TYPE-BELOW-BAND at the frozen tail.
- Mechanised decisions can be wrong at scale (a fold on weak E1 evidence, a define that should be a union). T3's 30-row stratified check is the guard; a sample error rate above a few rows sends the classifier back before the header batches, never past them.
- Rung-S re-sweep cost: about 9.9 h of cycle wall for the band at T2's rate (4.48 min per 1k TNC sites), header fan-outs about 1-2 min each. The bottleneck is the decision step, which T3 mechanises.
- The literal lever 0 is agent-priced and open-ended (P36: 9 sessions). T10 is the stop that turns an overrun into a developer ruling, never a silent narrowing. It fired; the ruling (2026-10-17) replaced literal 0 with walled survivors.
- A wall tag can become a relabel, not a judgment: a class-wide tag on weak evidence reads as a wall without one. Guards: a vocabulary row needs a pass and an evidence pointer; T20 proves each class-wide tag on a probe and gives dissenters their own tag; the record counts walled rows as residue, never as fixes.
- T11 writes its walls before the vocabulary exists (it runs under the installed wording), so its strings may not map one-to-one onto tags. T19 maps them and states any it cannot; it never invents a wall for a row that has none (that row goes back to a probe in T20).
- The T11 wave is long (about 14 h at the cap) and touches many TUs, including src/800.c; T18 waits for it so no crack batch races the decl fix.
- Lever cracks and rung D signature edits respell bodies, so per-site cast residue goes red after each (C0528): re-run `--residue` before every task's verify.
- Asm-body routines moved to assembly units could read as leaving the census. Only evidence that the original was hand-written assembly justifies it.
- 3.39 numbers differ by tree (T10 vs T9 TNC figures; P37 vs P39 census dirs by about 5 sites). Baselines come only from T1's census on the start commit.
