## Rationale
- Order: baselines first (T1, R83). The harness before the campaign (docs/gen3-handoff.md:233-235): names ledger and scanner (T2), then the rename tool with its two controls (T3). The shared form: writer, ledger re-keying and a pilot (T4) before the fleet; C classes (T5) before D and B (T6), because one name-blind text per class is nearly byte-neutral by construction and proves the batch loop at volume, while a D class needs an exemplar and a B class a registry repair. Trampolines (T7) once the parameter machinery exists. The ranking (T8) counts per unique body, so it does not depend on the conversion's progress and may run while a conversion task waits. Record (T9), gate (T10), close docs (T11), cleanup (T12).
- Known rename in scratch: the scope puts the machinery before any name, and 3.43 owns names; a worktree rename (C0546) proves the tool, the scanner and the per-binary gates without landing one. The control is independent of the scanner: its candidate set is compared with a plain `git grep -n -i` of every spelling.
- Planted miss of a kind the byte gate cannot see (a ledger row, a registry member, a tool control, a comment): a stale call already fails the link, so the scanner proves its value where the build is blind; T3 shows the gates green on it and the scanner red.
- Scanner and rename tool are separate programs and the scanner does not import the tool's matcher: one shared matcher would hide its own blind spot.
- Ledger fields are rule 1's (docs/gen3-standards.md:49-59). A `guess_` name without a basis row fails from 3.42 on (0 today, so free); curated names without a citation row are counted, not gated (3.43 gates them).
- Ghidra once: the only steps that need :8080 free are T3's mirror leg and the six proofs; both run in T10, so the developer's server keeps running until the gate.
- Effort: T8 is the one `effort: high` task: how xrefs, struct ownership and fan-out combine into one rank is a judgment no test arbitrates (docs/decision-log.md:1655-1667 warns that nins x reach over-counts); its coverage, denominators and two independent counts are tested.
- Coder tiers: all in-house (card). The stop rule for classes the gate rejects is the developer's (Developer decides).

## Risks
- Ledger re-keying is the conversion's main failure mode (R3.42-004): every gate keys on the file path, so a batch converted without re-keying turns lever_census `--strict --residue`, type_census `--check-casts --residue`, the lying check and verbatim_check red at many rows. T4 proves the re-keying on the pilot before the fleet.
- Context-dependent texts: a shared text compiled in another file can differ (declarations in scope, a `__FILE__` use, a jump-table carve, an -O0 split file); the gate rejects it and the reason codes exist (JTBL-CARVE, O0-LOCAL, TU-CONFLICT, GATE-REJECT, CROSS-SPACE). If many classes end there, "0 left" is not reachable without the developer's stop rule.
- The text oracle: at `--scope all` the deferred same-address duplicate texts (377 texts, 1,636 sites) count as violations; T1 checks that each belongs to a cross-address class, or the milestone's S1 0 needs more work than the 3,801.
- D exemplars may drop a legibility gain present in another copy or carry a lever marker to every site; the rule is logged per class, and `--reexemplar` exists.
- Metric drops from de-duplication: lever and raw-cast site counts fall as copies collapse into headers; the series and the docs must say why (T9, T11).
- Scanner false comfort: the candidate set must include every spelling (C0468: a bare-name dedup hid three quarters of a rebase); the positive control compares it with an independent grep. An over-broad history list hides stale references; it is a short closed list, reviewed in T2's summary.
- Name-ordered linking: a data rename can move bytes where the linker orders symbols by name (common symbols, sorted sections); the per-binary gate is the arbiter, and any such case becomes a cookbook entry.
- Trampoline callee inside an `__asm__` string: stringification or an operand may not survive maspsx; T7 proves one family first.
- Ghidra: the running server blocks every headless step, and the stop needs the developer's OK (R49); the rebuild and R22 must never overlap (`make clean` wipes build/ghidra_rebuild/proj).
- tools-health is longer than one 285 s tool call; the card's "foreground" note predates 3.41 T5's addition; 3.41 T10 and T12 ran it through tools/run.sh.
- Evidence kinds for 3.43: rule 1's list has no kind for a name proven by matching Sony's library objects (69 of the 1,080 curated names carry such a note); 3.43's citation rows will need the developer's amendment, and 3.42 keeps the list in one constant.
- Field and type renames are compiler-checked in build inputs; the scanner covers linker symbols, and 3.43's planner decides whether fields need its non-build scan.
- Disk: 26 GB free; the worktree build and R22 fit; .run/ holds 19 GB, including .run/P41 (R87).
