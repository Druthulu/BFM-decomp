- Merge evidence (milestone; DECIDED): a fold rests on cited evidence only. (3) A shared body: one h_exact class whose copies type the same slot differently. Type renames follow into it (T3). docs/struct-twins.md's apart section is generated from it, so the doc and the ledger cannot drift.
- Deterministic links (C0582): fixed input order and stable tie-breaks; two runs on one tree give the same components and targets. A component's target is its real type when it has one (an SDK type its value is passed to, a ledgered name), else the member with the largest reach(T), ties by name.
- DECL-PARAM (Developer decides 2): a declaration whose struct parameter names another type than its definition is evidence class (2), measured in T2. After the folds, T8 adds the rule to sig_evidence so the signature gate sees parameter types; disagreements the folds leave are ledgered with their cause, never edited (scope: prototypes touched only by a fold).
- Effort: T2 is the one `effort: high` task: what counts as a link in each class, when a component is safe to fold (width conflicts, load-bearing sizes, hub slots) and how a target is chosen are judgments no test fully arbitrates, and every fold copies them. Its selftest proves the mechanics; the review judges the rest.
- Name scope (milestone "the surviving types and the fields of the top types by leverage named, cited or guess_"): every surviving type, and every accessed field of the top 20 surviving types by reach(T), is cited or `guess_`; none is left no-evidence, since its accesses always give a basis to quote, and a thin basis gives a low-confidence guess (card: a prefixed best guess beats a bare placeholder). pad<HEX> bytes are never accessed and never named. ## Risks
- The evidence may link far fewer types than "a few hundred real types" suggests, leaving many no-evidence placeholders: the milestone still holds (no-evidence is a disposition), the survivor count is reported as measured, and T2's review sets the naming scope; nothing is folded on a look-alike to reach a number.
- Over-merging: links are transitive, and one wrong link (a generic buffer pointer, a void *-like slot, a callee whose parameter receives many unrelated types, a pool or list helper) can merge unrelated types. T2 refuses hub slots, names them, and the review sees the largest components.
- Width conflicts and sign mixes inside a component (773 census clusters carry one today): a fold needs one width and sign per accessed offset; a conflict keeps the members apart (the cause cites both accesses) unless a union member reproduces both views byte-identically.
- Load-bearing sizes: a fold that grows a type changes sizeof, array strides, pointer arithmetic and struct copies; such a fold keeps the size or is refused; R22 catches what the static check misses.
- Controls: folds or renames touching MATRIX_L48, Prim_8016E7C8 or D_800A651C's types move type_census controls 2-4 (type_census.py:1694-1715); the task re-points the control in the same commit with the reason, never to make a failure pass.
- Generated blocks: once retired, include/struct_types.h is hand-maintained; a later run of head_types.py or `restruct.py --decide-band --write` would clobber the folds unless both refuse (T6).
- Spelling-keyed tools (C0572): a type rename silently drops types from leverage_rank (:450), restruct (99 mentions), type_census and the 3.40 configs (type_folds.tsv, tnc_band.tsv) unless each follows; T3 proves census-neutrality before and after a pilot rename.
- Field renames: a field name is not unique (unk10 in hundreds of types), so a text rewrite renames other types' fields. Only the compiler-proven path (owner-typed accesses, 0 "has no member named", identical objects) is allowed; a member spelled inside a SHARED_FN body or a common.h macro is checked at every expansion.
- Cost: every header edit rebuilds the fleet: R22 per batch (about 4 min alone), type_census (about 6 min) and `struct_twins --write` per batch, tools-health (about 21 min) at each task end.
- The live import replaces type rows in the developer's Ghidra project: C0554's backup first, the program-row guard, the export cmp; never the full merge output (it re-applies committed function and comment rows over live edits).
- Ledger drift: the disposition ledger, docs/struct-twins.md, names.tsv and the types worklist move in the same commit as each batch; the gate re-verifies cites against the current tree, so a later edit that removes a cited line fails it until the row is updated.
- Disk: 24 GB free; scratch baselines and worktrees take a few GB each; each task deletes its own (T13 checks).
