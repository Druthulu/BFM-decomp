## Rationale
- Order: baselines first (T1), so every gate change is measured against a known verdict and runtime. Tool bugs (T2) before the gates, because `--no-cache` and the stale twins default sit under the census T3-T5 rely on. Return-type detector (T3) before its fixes (T4) before the `--check` alignment and wiring (T5), so tools-health turns green once, not red-then-green. The attribution fold (T6) lands in `lever_census --check`, which tools-health already runs. Ghidra types (T7) are independent of the census gates but read the final headers, so they follow T4 (T4 may edit prototypes, not structs; T7 may run in parallel with T5/T6). The live-DB mirror (T8) waits for the R32 answer. The record (T9) and the gate (T10) come last; close docs (T11) after the gate, as in 3.40.
- `--check` semantics: aligning the raw-cast clause to the residue-ledger measure is a change to a gate's meaning, so it is written down as a developer decision with the recommendation, not done silently (house rule: never redefine a term to make a failure pass). The raw count stays printed and in the readability series.
- Return lies in scope: the gate's job is to stop 3.38-3.40 regressing before renames; renames on a lying prototype would carry the lie. If T3 counts more than 300 functions, T4 stops after bucketing them (by return-type pair, caller-use pattern, shared-header fan-out) and Claude brings the buckets to the developer, who picks the stop rule.
- Ghidra type set: the 6 programs with committed files are the rostered set `ghidra_roster.py --check` and the proof already cover; each gets the canonical types its translation units use (census use), and every canonical type lands in at least one proven program (main carries the engine types). Generated type rows are a generated artifact: one tool writes them from the headers, a freshness check fails when the headers moved, and they are never hand-edited (H1). Whether they share the hand-authored `<prog>.jsonl` or sit in a generated sibling the rebuild imports first is the T7 expert's design call, with the proof's byte `cmp` kept exact.
- Layout truth: Ghidra struct offsets must equal gcc's. T7's control compares a sample of exported Ghidra struct field offsets and sizes with gcc's own (audit-cdecl / `offsetof` through the pinned cc1), plus the rebuild's negative control (one mutated field → PROOF FAIL).
- effort: no task is `effort: high`; every done-when is arbitrated by a tool (the gates, the proof, R22).
- Coder tiers: all in-house (card: cracking is DeepSeek-only and nothing here cracks; the rest is gate design, tool edits and doc work).
