## What cracked each item

- **func_801880E0** (pin $18 `w`, pin $0 `zr`): the G02 family trick applied to
  this twin — `flag2/flag3/flag4` as `s16` (the HImode copies escape cse's
  equivalence class, combine turns the sign-extend back into a move), `w` a
  local fed from the parameter, and `ot = func_800D27DC(...)` split before the
  return so `ot` wins $s1 in global-alloc. 1 try.
- **func_80182ED4** (pin $2 `t`, $3 `u`, $0 `zr`): the target's `move v1,v0` is
  `u = t + $0` — a HARD-register addend, so combine cannot fold it and cse
  never equates `u` with `t`. Lever-free: route the copy through an s16 temp
  and hoist it above the branch (`tmp = (s16)t; u = tmp;` before the `if`), so
  the copy and its use sit in different blocks; the HImode copy escapes cse2's
  equivalence class (G06's trick), the sign extension folds away (t is already
  a sign-extended s16) and the copy survives as `or v1,v0` in the bnez delay
  slot. 5 tries.
- **func_8017E6EC** (pin $2 `t`): the residual was the constant 0x10 vs the
  global `t4` in global-alloc (local-alloc gave $2 to the block-local constant
  and $3 to the global — the mirror of the target). Fix: store the constant
  through the existing global `c` (`c = 0x10; unk1C = c;`), which makes the
  constant a global pseudo too; global-alloc then hands $2 to `t4` and $3 to
  the constant. 1 try.
- **func_8018302C** (pin $0 `z`): same shape as func_80182ED4 (`c = v + $0`).
  An s16 temp makes the copy survive as `or v1,v0`, but combine then rewrites
  the `slti` operand to the copy (the compare reads v1, the target reads the
  load's v0); a u16 temp keeps the compare on the load but adds

  (`// !FAKE: do-while`): the loop-shaped live range keeps the copy in v1 AND
  leaves the `slti` on the load's reg v0. 33 tries.

## For the expert

- The reusable finding: **a copy that cse would propagate can be kept alive by
  routing it through an `s16` temp** (`tmp = (s16)x; y = tmp;`) — the HImode
  copy escapes cse2's equivalence class (G06's trick) and the sign extension
  folds away when the value is already a sign-extended 16-bit one. If the
  copy's use is in a different basic block than the copy, the copy survives the
  whole pipeline as `or rd,rs`.
- The follow-on trap: once the copy survives, combine may rewrite an
  *unrelated* operand (the `slti` of a compare) to the copy, because gcc now
  knows the two values are equal. Wrapping the copy in `do { } while (0)`
  (loop-shaped live range) restores the target's operand choice.

  item) are updated; every MATCH's `win.c` re-verified at score 0.
