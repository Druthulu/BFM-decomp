# T7.c2 — function-pointer-array fields in tools/ghidra_types.py

## Change
- `tools/ghidra_types.py`: new `_fill_dropped(fields, mbody, rbody, where)`, called by `read_headers` per definition after
  comment attach. Per depth-0 member statement: `cdecl.parse` is the second reading; a declarator struct_layout dropped with
  chain `ARR+ PTR FUN` (fn-ptr array) -> field `type="void *", stars=1, dims=<ARR dims>` (struct_layout's own fn-ptr reading),
  so `composite` places `/void *[n]` len 4n at gcc offset; Resolver layouts of embedding types follow. Any other drop, a
  cdecl parse failure, a name/count mismatch, or a bitfield statement whose field count != top-level comma parts -> model
  error (`--check` fails). Nested bodies recurse.
- `read_headers` returns `(walks, misaligned, errors)`; `Model.errors` starts from them.
- WARN in `summary` removed; replaced by a model error for any struct/union with no components (silent shell can't recur).
- struct_layout.py / type_census.py untouched.
