## Moves that cracked

- func_80150170: `s16 a[4]` / `s16 b[4]` instead of `u8 a[8]`/`u8 b[8]` (same stack layout, sp+16 / sp+24) and index
  elements. The compare `a[1] < b[1]` stays `lh`; the arm stores of `a[0]/a[1]/a[2]` then emit a fresh HImode `lhu`
  instead of reusing the sign-extended compare value — exactly the target's reloads. Tail loads stay
  `*(u16 *)(a + 0)` / `*(u16 *)((u8 *)a + 4)` (`lhu`). Frame vars 40 -> 24 (frame 56). 141/141 includers 0.
- func_80175820 / 758FC / 759D8: read D_800B9A02 through a struct member — `struct S9 { u16 v; }; struct S9 *sq =
  (struct S9 *)&D_800B9A02;` and use `sq->v` for every `*q`. The load is now MEM_IN_STRUCT_P, so cse.c:7564-7577
  (nonscalar store from a PLUS address) plus invalidate_memory (cse.c:1713-1716, `nonscalar && p->in_struct`) removes
  the cached value at the `ptr[K]` store; the post-store `lhu 0(a2)` reloads and the 16-byte vars frame then match
  byte-for-byte. 141/141 includers 0 on each. (759D8 needs the `struct S9` declaration at the top of the block: GCC
  2.7.2 rejects a declaration after the early `if (D_8011F7B1 != 0) return;`.)
