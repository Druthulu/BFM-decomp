## Moves that cracked (all plain C, no asm / register steer / barrier / keepalive)

- `func_8018656C` — the launder `__asm__("" : "=r"(diff) : "0"(diff))` in the second block
  becomes `do { } while (0);` plus a **real second set** of diff (the same expression, so the
  value is unchanged).  The empty asm is what stopped gcc folding `if (c) return 1; else
  return 0;` into `return c`; the do-while keeps the CFG shape and the second set keeps diff
  a fresh value, so the two arm tails stay duplicated.  win.c: 66 ins, byte-identical.
- `func_8017D73C` — the launder on the trip count `n` becomes `n = (s16)n;` (n is 0x14/0x10,
  so the cast is a no-op).  The asm made n opaque, which kept the 2nd and 3rd
  `if (n != 0)` tests; the real second set does the same.  win.c: 177 ins, byte-identical.
- `func_8017D9D8` and `func_8017EF0C` (the same shape) — the launder
  `__asm__ volatile("" : "=r"(v0) : "0"(v0), "m"(pad));` becomes `do { } while (0);` plus
  `v0 = (s16)v0;` (v0 is a sign-extended s16 field, so the cast is a no-op), and the dead
  `s32 pad;` becomes `s32 pad[2];` because the asm's "m" input is what made pad
  address-taken and gave the target its 32B frame.  win.c: 50 ins, byte-identical.
- `func_801813B0` — the twelve `__asm__("" : "=r"(v) : "0"(v));` on v become six
  `v = (s16)v;` (v is a sign-extended s16 field).  The twelve empty asms had only raised
  v's reference count; six real second sets buy the same pressure, and the allocator then
  rematerialises the loop-invariant compare constants into the delay slots like the target.

## Walls (mechanism + evidence)

- `func_80183098` — WALL `cse-const-addr`, best 10.  The target keeps one `la $s1,
  D_80126B5E` and reads the camera x/y off it (`lh v1,4(s1)`); plain C gives cse's
  find_best_addr a *known constant* base, and it rematerialises the y address
  (`lui v1,0x0 ; lh v1,4(v1)`).  The empty asm made the base opaque, so only the register
  form was possible.  A plain-C base is always constant here, so the address would have to
  come from a load, which costs instructions the target does not have.
- `func_8018C730` — WALL `flow-unused-result`, best 6 (18 ins against 23).  The two asm
  statements are the only thing that makes gcc materialise the *dead* constants
  (`&func_80172710`, `0`) into v0 at the return; the function is void, so plain C drops the
  value (`return (s32)func_80172710;` in a void function is accepted with a warning by
  gcc 2.7.2 but the value is dropped).  Removing the levers needs the function to return the
  value, i.e. a signature change, which the task forbids.
- `func_8017D96C` and `func_8017EA24` — WALL `sched1-order-li-load`, best 2.  The v1 lever
  becomes `v1 = (s16)v1;` (v1 is mode & 3) and the e lever becomes `do { } while (0);`; a
  width cast on e truncates the pointer (the target loads it with `lw`), so it is not
  faithful even though it reaches 1.  What is left is one instruction ordered the other way
  round: the target's case0 arm is `li a0,409` then `lw v1,32(s0)`, this body has the load
  first.
