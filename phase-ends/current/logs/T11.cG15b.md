## Moves that cracked

1. **func_80190D70 / func_8018CD5C (twin bodies) — MATCH, 0.** The tree's re-tie
   `__asm__("" : "=r"(vol) : "0"(vol))` gives `vol` a SECOND set, which kills sched1's
   `birthing_insn_p` LAUNCH_PRIORITY boost on the quotient's birth (cookbook §350): with
   one set the quotient's birth is boosted, the VOL multiply is hoisted behind the PAN
   multiply and the shared magic constant 0x66666667 is materialised in `$v0` late
   instead of in `$a0` at the top of the case-0 block.
   Lever-free, plain C: **`vol = vol | 0x3000;` right before the call** — a real second
   set of `vol` (the G11 "compound assign = a REAL 2nd SET" recipe). The value is
   unchanged: the call argument ORs 0x3000 again and masks 0xFFFF, and the extra `ori`
   folds into the target's own `ori a1,a1,0x3000` (192 ins = target). Placement matters:
   the statement must sit just before the call, after `sx = sx << 8`, or the `bne` delay
   slot takes the wrong instruction.
2. **SCAN (ov_SC06_033_jr_8018D98C:3097-3111) — MATCH, 0.** The census scoped the site at
   line 3102 to a body named `SCAN`; the scorer compares the whole TU object (3991 ins).
   The tree's re-tie keeps `&D_801C8344` rematerialised at every site instead of hoisted
   into a callee-saved register. Lever-free: **drop the re-tie and add the §373 DEAD-RESET
   CSE-BREAKER `_m = 0;` after the call** — cse's forward scan invalidates the address
   class at the reset, so every site re-derives `la $a1, D_801C8344`; the reset is dead
   and flow drops it (zero bytes).

## Walls (with evidence)

1. **func_8018FB5C — `sched1-birth-boost-dbr-delay` (best 2, 32 tries).**
   The re-tie does TWO jobs: (a) it is the second set of the pinned `$16` pseudo, which
   kills sched1's birthing boost (without it the call's `li a0,16` is hoisted above the
   `move s0,a2`, score 2); (b) it is a zero-width RTL insn between the birth and the
   call's argument setup, which keeps the `li a0,16` out of the jal's delay slot. A
   plain-C loop (`do { rgb = rgb; } while (0);`, `while (0)`, `for (;0;)`) supplies (a) —
   the copy survives as a second set — but then the `li a0,16` falls into the delay slot
   (score 4). Every 2nd-set spelling that cse/combine folds away (self copies, casts,
   `rgb |= 0`, `rgb += 0`, temp copies, `u32`/`s16` widths) leaves the boost alive
   (score 2). A surviving second set of a *pinned* pseudo needs a mode change, a volatile
   or an asm — all levers. Evidence: gcc -O2 99 ins = target; the diff is one instruction
   (`li a0,16` at slot 5 instead of 7).
2. **func_8017E4DC — `loop-biv-giv-rebase` (best 4, 32 tries).**
   The re-tie gives `q` a SECOND definition inside the loop body, and loop.c then prints
   `Reg 75: biv discarded, not induction variable`: `q` is not a basic induction variable,
   so the giv-combining pass never rewrites the three store addresses as (IV + const) and
   never re-bases `q`. Lever-free, loop.c prints `biv verified` + `Biv 75 initialized at
   insn 149: initial value (symbol_ref:SI ("D_801AAD6C"))`, combines the three givs and
   the new IV starts at D_801AAD6C+2: the stores become `sh zero,4(s0) / 2(s0) / 0(s0)`
   and q's init becomes `addiu s0,s0,2` (92 ins both, two constants differ).
   No plain-C spelling gives a pointer a second definition that emits no instruction:
   a self copy is removed by cse, `q += 0` / `q |= 0` are folded (`|=` is invalid on a
   pointer), and a mode change is impossible for a pointer. Re-spellings of the stores
   (`(u8 *)q + 6`, `(s32)q + 6`), of the 4th store (`(u8 *)D_801AAD6C + off` keeps the
   separate address but does not stop the re-basing), of the increment, of the statement
   order and of the loop shape (`for`, `do/while`) all stay at 4 or worse.
