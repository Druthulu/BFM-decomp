# T8.c5: PsyQ library names in main (R158) vs the PsyQ 4.0 headers (coder log)

Base ed2822bc70. Drivers: .run/3.44/t8/c5/ (measure.py, apply.py, dist.py, pad.py; mkbase/runall/pipe/cmp/objs/gen copied from c4).

## Header version
- tools/reference/psyq-sdk/PSX/INCLUDE/ = Programmer Tools CD, Library 4.0 (README June 1997, CHANGE40.TXT).
- Why: C0015 says BFM's libraries are PsyQ 4.0 USA (DTL-S2002 R2.0, tools/psyq/lib40). PSX/LIB/*.LIB on that CD is md5-identical to
  tools/psyq/lib40 (LIBGTE, LIBGPU, LIBCD, LIBSPU, LIBC2 checked), so these are the headers of the libraries main links.
  The 4.2 libapi/libpad objects (C0569) have no prototype row that disagrees here.
- Headers are Shift-JIS and CRLF: plain grep treats LIBGTE.H/LIBCD.H as binary (use `grep -a`); measure.py reads them as latin-1.

## Traps
- generalizable: a new typedef in struct_types.h needs `ghidra_types.py --write` (config/ghidra/types/*.jsonl), and its pad fields must
  be offset-named, or tools-health fails (check-structs runs before ghidra_types, so the second failure only shows after the first is fixed).
- generalizable: PsyQ 4.0 headers are Shift-JIS/CRLF: `grep` without -a silently skips LIBGTE.H, LIBCD.H, LIBSPU.H, KERNEL.H.
- A scratch recompile with a relative `-o` path fails in the assembler and leaves the old .o in place: cmp then reads stale bytes. Use absolute OUTDIR.
