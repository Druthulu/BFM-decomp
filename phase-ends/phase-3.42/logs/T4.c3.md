# T4.c3 — cross re-key: restruct rung-S rows to the headers; tools-health OK after cross1

## Change (tools/share_body.py, commit f6447a87e3)
- `Batch.moves` tuples carry the private def line (5th elt, census `i["line"]`); unpackers in rekey_ledgers / run_batch updated.
- New `rekey_restruct(moves, label)`: per header, one appended rung-S row (tu=header, unit=fn=SHARED_FN, addr None, header True, nhash = header body's, `rekey_of` = [[tu, unit]...], label `rekey_<label>`) built from each copy's latest rung-S row; entry lines shifted by (header def line − private def line); copies multiset max-union; a union differing from any copy logged; row fields from a copy whose verdict is in type_census.BACKED_S_VERDICTS, else first. Old rows never rewritten. Idempotent: header whose latest row has `rekey_of` skipped. run_batch calls it after rekey_ledgers, before restamp_residue (residue_rows merges onto it).
- New `--rekey-batch <label>` → `rekey_batch`: rebuilds moves from batch_<label>.json classes (minus rejected) + each header's `#define SHARED_FN <own>`/include sites (git grep); private def line from `git show <header provenance sha>:<tu>` (sc.scan_text); then rekey_ledgers, rekey_restruct, restamp_residue(residue_segments, `<label>_rekey`). Runs before the census.
- Union key ignores `line` except for KEPT(REINTERP) entries (gate matches REINTERP by line). Why: old rows' lines drift per copy (rows written vs older text; def-relative offsets differed by up to ~80, e.g. cls_a5af90662c87 89 vs 8), so a line-keyed union multiplied entries (first dry run: 73 unioned, cls_c1e849705c1e 67 → 120). cross1 has no REINTERP header sites (K: ALIAS 3, SIGN 18, WIDTH 16).
- kit-corpus regenerated: corpus copies of share_body.py and argcheck.py (the latter's T4.c2 edit had not been materialised).
