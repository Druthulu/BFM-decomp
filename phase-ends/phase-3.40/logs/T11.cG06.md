## Moves that cracked

1. **func_8017CE7C (MATCH)** — the pin put the incremented byte in `$2`; unpinned,
   gcc's local-alloc gave the byte temp `$3` and the constant 10 `$4`
   (score 10).  Wrapping the tail in `do { ... } while (0)` gives the byte temp a
   loop-shaped live range, so it outranks the return-value copy and lands in `$2`
   (score 4); splitting the constant-10 store out of the loop restores the
   target's store order (score 0).  The `do-while(0)` is a real C move, not a
   keepalive: the loop runs exactly once.
2. **func_8017E204 (MATCH)** — the `$0` pin made `v1 = v0 + zr` a real
   three-operand add (`addu v1,v0,$0`), so `v1` stayed a SEPARATE register from
   `v0`; cse could not forward `v0` into `v1`'s use, and the `move v1,v0` in
   the target's branch delay slot survived.  Unpinned, cse's copy-merge deleted
   the copy and the whole `move v1,v0` (score 12).  Routing the copy through an
   `s16` temp (`t = (s16)v0; v1 = t;`) puts it in a different cse equivalence
   class, so the copy survives and `v1` keeps its own register — score 0.
3. **func_80182F44 (MATCH)** — the `$2` pin kept the loop-invariant constant
   `0x26E` inside the loop (`li v0,622` before the compare, inside the loop
   body); unpinned, loop.c's `move_movables` hoisted the constant into the
   prologue (`li s4,622`) and the loop then compared against `$4` (score 8).
   Cookbook C0421: a pseudo with a SECOND set is not eligible for the hoist, so
   a second `kind = 0x26E;` at the end of the loop body keeps the constant in
   the loop — score 0.  (Five placements of the second set all scored 0.)

## Wall

4. **func_80187250 (WALL, best 1 of 107)** — the `$2` pin makes `return r` a
   self-copy in `$2` that reload deletes, so the r==0 edge is EMPTY and jump.c
   collapses it into `beqz $v0, <epilogue>`.  Unpinned, cse2's PRE const-folds
   the pseudo `r` to the constant 0 on the equal edge, so the r==0 block becomes
   `move v0,zero; j epi` — byte-identical to the shared ret0 block — and
   cross_jump merges the two; the branch then lands on ret0 (108c) instead of the
   epilogue (109c).  ONE word differs, the branch target.  107 shapes were
   tried (temps, cross-mode copies, pointer-mode compares, `goto`/do-while/switch
   restructures, init-at-decl, scopes, a second set); all scored 1, and the
   shapes that moved the ret0/store tail scored 8.  New wall tag
   `cse2-pre-fold`.  Full list in the item's `notes.md`.
