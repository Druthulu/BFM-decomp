## Item 1 — func_801627E8 (ov_SC01_077_jr_8015C32C)

- start 15:03 MDT, end 16:34 MDT — 91 min wall (the sweep over all R2-R46
  families on two different bases dominates; the decisive candidates came at
  the end).
- tries: 46 scored bodies (21 + 15 from the two recipe sweeps, 10 hand-written).

**MATCH, best 0.** The lever was a §21 re-tie launder
`__asm__ __volatile__("" : "=r"(p) : "0"(p))` on a `register u8 *p __asm__("$4")`
pointer, together forcing the full address `&D_8011F750` to be materialized into
$a0 (`lui a0 / addiu a0,a0`) before `lbu v0,0(a0)` instead of %lo-folding it
into the load.

The move: the materialization is not a launder effect — it is the *argument* of
the dispatch call. The MAIN_012 twin of the same function
(`src/ov_MAIN_012/ov_MAIN_012_jr_8015A3C8.c:6103`) spells it plainly as
`D_80180F24[idx](p)` with `p` a plain local. The lever-free spelling is the
same shape with the argument explicit and the table element cast at the call
site (the project's established idiom, cf. moves.md func_80157BC8 /
func_800CCBCC):

```c
void func_801627E8(void)
{
    u8 *p = (u8 *)&D_8011F750;
    s32 idx;

    idx = *p;
    if (idx != 0) {
        idx = idx - 1;
        ((void (*)(u8 *))D_801896C0[idx])(p);
    }
}
```

Score 0 (19 ins, byte-identical). No pin, no launder, no asm, no volatile; the
file-scope decl of `D_801896C0` is untouched (only the call site is cast), so
no declaration outside the body changes and no caller changes.

Rejected variants (all in `<dir>/`, with scores):
- a1 / c2 / c3 / c4 — drop the launder, keep the pin: 7. The pin alone does not
  force the materialization; the address is %lo-folded into the lbu.
- e1 — pointer reuse through a second local `q`: 7.
- e2 — pin + `(void)&p`: 11.
- f2 — the call without the argument: 7 (no $a0 materialization).
- f3 — pin AND the cast: 0, but the pin is then unnecessary; win.c keeps the
  pin-free f1 spelling.
- recipe sweep (R2/R3/R4/R5/R6/R7/R9/R12/R27 …) over the lever-free body and
  over the pin-kept/launder-removed body: best 7 (R27 port = the MAIN_012 twin,
  which uses a different table `D_80180F24`, so it differs in 2 reloc words).

Evidence for the row (gcc pass + mechanism):
`launder+pin both gone: call-site cast ((void (*)(u8 *))D_801896C0[idx])(p) makes
the arg materialize &D_8011F750 into $a0 (MAIN_012 twin shape), same
lui/addiu/lbu 0(a0)`.
