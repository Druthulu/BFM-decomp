## The moves that cracked

1. `pin | func_8012944C | MATCH` — **do-while → goto loop**. The src body pins
   `p` to `$17` and loops with `do { … } while (i < 2)`. With the pin, gcc 2.7.2's
   loop.c cannot touch `p`; without it, loop.c strength-reduces `p` into a second
   induction variable (`addiu s1,s0,58` + `lhu v1,-6(s1)`) and `p` lands in `$s3`
   (76 ins against the target's 72). As a goto loop (`loop:` … `if (i < 2) goto loop;`)
   there are no LOOP notes, loop.c leaves `p` alone, `p` keeps `$s1` and `base`
   `$s0` — **byte-identical on 141/141 includers**. `win.c` holds the lever-free body.
2. `pin | func_8003DF8C | MATCH` — **`u16 i; u16 j;`**. The src body pins `zr` to
   `$0` and spells `i = arg0 + zr; j = arg1 + zr;`; the target keeps opaque copies
   of arg0/arg1 in `$a3/$t0`. A copy into a **16-bit** destination is an HImode
   copy, and gcc 2.7.2's cse propagates only word-mode copies — so the copy
   survives and the parameters are copied into the callee-saved registers the u16
   needs (they are live across the calls). Score 0, 175 ins.
3. `pin | func_80181E64 | MATCH` — **`s16 v;` and the store reads `v`**. Same
   mechanism: the HImode copy `t = v` escapes cse; because `v` is still live at
   the copy the copy is not folded away, and the reverse propagation then puts
   the store on `t`'s register. The target's opaque `move s8,v0` survives. Score 0,
   103 ins.

The generalisable lever from (2) and (3): **a copy whose destination is 16 bits
escapes cse**, so the opaque copy the target keeps can be reproduced by a type
width instead of a `$0`-pinned add — provided the copy's source is still live at
the copy (otherwise combine folds it away again).

## Walls (mechanism + evidence)

* **func_801415C0** — `lreg-qty-order` (37 tries, 163 min). gcc 2.7.2's
  local-alloc gives the two locals `c`,`d` the first callee-saved registers
  (`$s0/$s1`) and the globals `a`,`b`,`e` the next three (`$s2/$s3/$s4`); the
  target wants `a=$s0,b=$s1`. The `.lreg`/`.greg` dumps show `c`/`d` are locals
  (one set each) and `a`/`b`/`e` globals (several sets), global priority order
  a 5000, b 4615, c 4285, e 3636, d 3000 (`floor(log2 refs)*refs/live*1e4`).
  Tried: declaration order (all six permutations), widths (u32/u8/s16), init at
  decl, one-set values, split values, e1/e2, the statement order, dead
  self-assignments. No plain-C spelling moves `c`/`d` into the global bank or
  flips the order. Best 40.
* **func_800D0D7C** — `cse-opaque-copy` (77 tries, 81 min). The pin `zr` makes
  `r = now + zr` and `h = arg0 + zr` emit `addu rd,rs,$zero` copies that neither
  cse nor combine removes (the src's own RC-12 note), and the opaque copy also
  stops combine folding `r & 0xFF` back to the D_80078EB0 lbu. The 16-bit trick
  that cracked func_8003DF8C only half works here: with `u16 h` the `h = arg0`
  copy survives (`move a3,a0`), but `r = now` is a pseudo→pseudo copy in a
  function with no call, so combine still folds it and `r & 0xFF` folds to the
  lbu. Tried: every copy spelling (+0/-0/|0/&-1/^0/*1//1/<<0/>>0/~(~/v)), the
  widths of `now`/`r`/`h` (32 combinations), the conditions reading `now` instead
  of `r`, the `dead[2]` frame array. Best 16.
* **func_80180480** — `lreg-v0-local-first` (57 tries, 79 min). The target puts
  the pointer in `$v1` and the value in `$v0`; local-alloc gives the
  first-created pseudo (the pointer) `$v0`, which adds four `move v1,v0` copies
  of the call results (58 ins against 54). The allocation table shows the pointer
  at 4 refs/12 insns and the value at 3 refs/6 insns, so the pointer outranks the
  value. Tried: declaration order, init at decl, widths, typed pointer, one-set
  value, a subtraction temp, a dead store, the pointer's type as char*/void* —
  all 19. Best 19.
* **func_800D2650** — `reload-reg-choice` (74 tries, 83 min). All four pins
  removed the body is 99 instructions against the target's 99, but the two
  stack-parameter reloads land in `$t0/$v1` the other way round (`lw t0,16(sp)` /
  `lw v1,20(sp)` against the target's `lw v1,16(sp)` / `lw t0,20(sp)`) and the
  loaded byte and the constant 8 swap `$v0/$v1`. Tried: the cw/s_a6/a5/a6
  statement orders (10 permutations, with and without a separate cw2), dropping
  the s_a6 variable, the sVar2 constant split into its own variable, the order

  locals, an extra unused local. Best 9 (`c1.c`).
