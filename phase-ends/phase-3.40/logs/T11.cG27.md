## Walls (evidence)

- expand-void-return (clones): target keeps rv in $2 because the real function returns it;
  the TU def is `void`, so expand_null_return drops the value and flow deletes the dead
  rv sets. The keepalive keeps rv live but global-alloc assigns $3 (free after x dies);
  only a return (or the `$2` pin) coalesces rv to $2. A `s32` definition conflicts with
  the callers' `extern void` decls (compile error), and signature changes are out of scope.
- flow-unused-result (func_8017D730): target keeps a dead v1 = 0x7F - ((t*96)>>12) plus
  slti/li 31 in the second `rem == D_80185D04` branch; the call passes 0. Only the cmp
  keepalive + tmp3 $3 pin/keepalive force it; no real use exists in the target.
