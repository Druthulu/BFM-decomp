# R120 — GitHub issue discussions are never committed or named in commit logs
id: R120 · group: - · status: active · tags: - · origin: developer 2026-09-30 · added: 2026-09-30

**Rule.** Discussions of outward threads (GitHub issues and pull requests on this project or any other: the reporter's questions, our drafted replies, the reporter's handle, thread URLs or numbers) are never committed and never named in a commit message.

**Why.** The repository is public. Outward text is written by the maintainer, like a developer, per `docs/gen3-standards.md`; an agent's drafts and analysis of a thread are not that text. An issue thread holds the reporter's own words and identity, which are not ours to republish in history. History cannot be un-published once pushed.

**How.**
- A `discuss` agent on an outward-thread topic writes its record and any draft reply under `.run/` (gitignored), never under `phase-ends/`.
- A discussion record that does land in `phase-ends/*/discussions/` and names an issue/PR number or URL, or carries an `Outward: yes` line, is left unstaged by `tools/commit_task.sh`; the helper also refuses a commit message naming an issue/PR number or URL.
- Plan titles, plan change notes, logs and task summaries describe the technical work only (e.g. "formats.md corrections"), never the thread that prompted it.
- A record already committed is untracked with `git rm --cached` and gitignored; history is rewritten only on the developer's decision.
