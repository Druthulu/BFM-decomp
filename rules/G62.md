# G62 — Names and types are evidence-based, never guessed
id: G62 · group: - · status: active · tags: - · origin: decomp-architect; amended phase 3.45 T6 · added: 2026-11-14

A symbol is renamed only on a recorded basis (a string it prints, a cross-reference chain, a debug menu, a live-memory
datapoint, a community label with provenance). No evidence, no name — an address-named placeholder is honest and greppable.
A model may propose a name; it may never assert one. Types come from access patterns locked into the bytes; structure is
unified before any field is named. **At bank time:** a canonical type file exists from the first bank and grows one proven
field at a time; a draft may not bank a duplicate definition of a shape the file already has, nor a raw address cast (every
absolute address it touches is a declared, typed symbol); a width or signedness is proven by the bytes, never guessed — the one
place a type moves bytes, and the one the permuter cannot reach.

**Amended 2026-11-13 (the developer, Phase 3.45 replan, R182): exact layout twins of 3+ fields are one type.** Two or more
placeholder definitions of the same kind, size and exact layout (every field's offset, width and sign) with three or more
non-pad fields fold into one type on their shape alone; no shared-object evidence is needed. Small dense value shapes (fields
from offset 0 covering the size, at most 32 bytes) that recur as exact twins fold into one shared value type each, the PsyQ
type where one fits (SVECTOR, VECTOR, CVECTOR, RECT …). Other layout twins (1-2 fields, not a value shape) still need
evidence to fold. Names stay evidence-based: a fold merges types, it names nothing. Reason: the duplicates were made by the
tooling (3.40's per-cluster definitions), not by the game; "merge on evidence, never on layout look-alikes" kept 2,510 twin
types that a reader sees as one type. A fold is refused only when it changes bytes after a second attempt up the lever ladder (G57).
