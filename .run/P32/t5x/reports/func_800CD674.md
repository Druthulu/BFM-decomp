## Generalizable (cookbook candidate — "the birthing-boost vs dying-input-suggestion fork")

* A wrong-register residual where the target's register is a **pinned constant's register dying in that insn** is
  `qty_phys_sugg`: the consumer pseudo must be born there, single-death (a variable reused across blocks/prims is a
  global allocno and conflicts with the constant). Splitting the variable is the right move — but
* a fresh single-SET pseudo changes **sched1**, not just regalloc: `adjust_priority` glues its def to its use
  (`reg_n_sets == 1` + live dest), so any gap-filler role the old multi-set pseudo played is lost and the fillers cascade
  through the prologue. The tell: the regression rows are far from the edit and all in constant/`lui`/`ori` placement.
* Zero-byte cure for the pseudo that must NOT be boosted: a trailing `__asm__ volatile("" : "=r"(v))` — a second SET flow
  keeps (REG_UNUSED), `reg_n_sets = 2`, no boost, no bytes. Do NOT apply it to the pseudo that needs the suggestion: a
  volatile asm re-lives every hard register (sched.c/flow treat it as using+clobbering all), so the extended qty conflicts
  with the very register you want.
* The prior agent's "+1 pseudo displaces two hoisted constants" was a correct observation with a mis-read mechanism: it
  is not pseudo COUNT (regalloc) but `reg_n_sets` (sched1's birthing boost).
