## Mechanism findings (read from tools/reference/gcc-2.7.2, byte-checked where stated)

### F1. HYPOTHESIS.md's "P sat in $t0 with caller-save and was evicted at iteration 1" is REFUTED by the spill-reg order.
* `order_regs_for_reload` (reload1.c:3606-3700) runs ONCE, before the reload loop (reload1.c:694). It sums `reg_n_refs` of every
  pseudo homed in each hard reg (`hard_reg_n_uses`), then lists ZERO-use call-used regs first in regno order, then zero-use
  callee-saved, then used regs. `new_spill_reg` takes the FIRST entry in the needed class (reload1.c:1590-1640).
* $v0,$v1,$a0-$a3 carry pseudos here, so `$t0` (8) is the first zero-use GR reg — that is why every reload uses $t0. A pseudo
  homed in $t0 would make $t1 the first zero-use reg -> `Spilling reg 9` -> every `lw $t0,0x30($sp)` becomes $t1 (the S79
  `__asm__("$8")` probe measured exactly this, +30 rows). So NO pseudo held $t0 at reload start in the target either.
* `regs_explicitly_used` = flow's `regs_ever_live` copied at reload1.c:486 BEFORE pseudo homes are merged (mark_home_live at
  reload1.c:502) — it is the explicit-hard-reg set ($v0,$a0-$a3,$sp,$ra, the `$2` pin), all put in `bad_spill_regs`.
* Corollary: a caller-save area (§172 producer 3) can only come from a pseudo homed in a call-used reg R != $t0 that is NOT
  evicted (only $t0 and LO=65 are spilled), i.e. it stays in R through the final code. `save_call_clobbered_regs`
  (caller-save.c:349-470) inserts save/restore at every call where R is live (real liveness: live-at-start + REG_DEAD walk) —
  the target has none — so such a pseudo must NOT be live across any call while carrying a STALE `reg_n_calls_crossed > 0`
  (caller-save.c:264 tests only the count). And `caller_save_needed` is set only by the profitability paths
  (global.c:1085-1091 `CALLER_SAVE_PROFITABLE(refs,calls) = 4*calls < refs`, local-alloc.c:2209-2213), which also need every
  callee-saved reg in the allocno's `hard_reg_conflicts` (find_reg pass 1 takes any free callee-saved reg).

### F2. Where stale register info comes from (post-flow passes).
* sched.c:4949-4964: after sched1, `reg_n_calls_crossed` is overwritten with sched's count ONLY if the new count is nonzero
  or the pseudo is single-block (`reg_basic_block != REG_BLOCK_GLOBAL`); a multi-block pseudo whose def/use moved across a
  call keeps its stale positive count. Movement across a call is allowed only for insns whose regs already cross a call
  (sched.c:1732, 1893); loads never cross a call (sched.c:1930 unconditional dependence on `last_pending_memory_flush`).
  In THIS function no call block has a movable def/use (the post-call code in every call block is fixed by the bytes:
  K1 `addu $s5,$v0`, K2 `sll $v0,$v0,16`, K3 `addu $v1,$v0`, K5 loads/stores) — measured: the sched dump of the lhu draft
  prints no `crosses calls` change for any register.
* combine.c:44-62 documents what it does not update: `reg_live_length` never; `reg_n_refs` "in the rare case when a register
  is no longer required in a computation"; and combine.c:2309-2313 / 2332-2336 zero `reg_n_refs` of a deleted def's dest
  ONLY when `reg_n_sets` reaches 0 and the pseudo is not live at the start of block 0. `reg_n_calls_crossed` is never
  touched by combine.

### F3. The simplest producer of a never-referenced 8-byte slot at exactly 0x48 is reload1.c:658 (`alter_reg (i, -1)` loop).
* alter_reg (reload1.c:2309-2345) gives an 8-byte slot (align -1 = BIGGEST_ALIGNMENT) to every pseudo with
  `reg_renumber < 0 && reg_n_refs > 0 && !reg_equiv_constant && !reg_equiv_memory_loc`, in REGNO order. The three parameter
  pseudos (72/73/74) take 0x30/0x38/0x40; ANY later-numbered slotted pseudo lands at 0x48. vars 56+8 = 64 exactly.
* A pseudo that has such a slot but never references it in code = a "ghost": stale `reg_n_refs > 0` with no surviving
  occurrence, OR occurrences only inside no-code insns (`(use (reg))` — §172 producer 2 — or `(clobber (reg))`), AND it must
  fail allocation: with stale `reg_n_calls_crossed > 0` and all 9 callee-saved regs in its conflicts (via stale
  `basic_block_live_at_start` membership) and not caller-save-profitable, find_reg leaves `reg_renumber = -1`.
  (A ghost with calls_crossed == 0 or no conflicts is simply homed in $v0 and produces neither code nor slot.)
* S79's own instrument note confirms ghosts exist in this compiler ("the stranded pseudo is simply absent from every
  post-combine dump while flow's stale reg_n_refs keeps it an allocno") — the target's slot is a ghost of SOME species; the
  `lh`-orphan species at the u18 site is excluded by the `lhu` byte. The open question is which other post-flow deletion
  leaves a ghost here.

### F4. THE MECHANISM, byte-measured: the 0x48 slot is a "ghost" pseudo — a stranded middle temp of a 3-insn combination.
Reproducer (`.run/P32/t5x/work/func_80032A74/ghost1.c`, S79's minimal case) with `-df -dc -dl`:
* flow: 72 = (mem A) [HI], 74 = (ashift 72 16), 73 = (ashiftrt 74 16), 75 = (plus 73? -1) ... `Register 74 used 2 times`.
* combine: insn 10 = `(set (reg:SI 73) (sign_extend (mem A)))` [lh], insn 11 = `(set (reg/v:HI 72) (subreg:HI (reg:SI 73) 0))`
  [the kept narrow value, rewritten as a copy by combine.c:1887-1930, the SIGN_EXTEND-only "narrow load then extend, both
  live" split]. Pseudo 74 appears in NO insn.
* lreg: `Register 74 used 2 times across 2 insns in block 0; dies in 0 places; ST_REGS or none.` — flow's `reg_n_refs` was
  never zeroed because combine's zeroing (combine.c:2306-2313) is skipped whenever `newi2pat != 0`; with zero occurrences,
  regclass gives it ST_REGS (no allocatable reg in that class on this target) and alternate NO_REGS, so find_reg can never
  home it; local-alloc never sees it (no births). `Register 73 in 2 / 75 in 2` only.
* reload: alter_reg(74,-1) → `vars= 8` (an 8-byte slot, `.frame $sp,8`), code = `lh; move; beq; addu; sh` (no reference).
So the frame residue = ONE ghost pseudo; producers = the try_combine paths that leave `newi2pat != 0` while i2dest vanishes:
(a) combine.c:1887 SIGN_EXTEND-of-narrow-load with the narrow reg still live (the known §172 producer-2 "orphan"; it FORCES
`lh`, which is why the u18 site cannot pay: the target's idx-244 load is `lhu`, and this path tests `== SIGN_EXTEND`);
(b) the generic "PARALLEL of two independent SETs" split (combine.c ~1698-1760) when the kept set is I1's (added_sets_1) and
I3' folds I1's source so that i2dest disappears.

### F5. Why path (a) — the only ghost species this compiler produces from a memory value — cannot fire on THIS code.
* Path (a) (combine.c:1887) keeps the narrow value as `(set V (subreg:HI Y))` placed in I3's slot, i.e. AFTER `lh Y` and
  BEFORE Y's consumer, so V and Y are simultaneously live: the copy is a real `move` (ghost1: `lh $2; move $3,$2; beq $2`)
  unless a LATER same-block insn consumes V and combine folds the copy into it (LOG_LINKS never cross a block). S79's u18
  lever worked exactly so (the `(s8)u18` use is in the same block) — and it forces `lh` because the path tests
  `GET_CODE (...) == SIGN_EXTEND` (a `lhu` promotion is a single `zero_extendhisi2` insn from memory: no middle temp exists).
* A second PROMOTED use in another block does not help: (i) if that block is the branch target with LABEL_NUSES==1, cse
  (-fcse-follow-jumps) follows it and folds the second promotion into Y before flow — measured: probes n0a/n0b/n0c
  (`s16 n0 = D_800C5328[b*2]; if (n0<0){...} else n = n0;`) give `vars= 56`, flow shows `REG_DEAD (reg/v:HI 118)` on the
  first promotion, and the code grows `move $18,$2` (+86 diff rows: the N=Y copy is not coalesced because Y stays live for
  the branch); (ii) if it is the fall-through block, cse does not fold it, but combine cannot reach the copy across the
  block boundary and MIPS has no register `sign_extend` insn (extendhisi2 is a MEM-only internal + an expand to a shift
  pair), so the `sll/sra` pair AND the `move` survive.
* The target's nine `lh` results each have exactly one consumer in their own block (n's later uses — `sll $a0,$s2,2`,
  `sh $s2,0x10($s0)` — are of the FINAL n after the D_800C532A/`n = 4` re-definitions, so they cannot be spelled as uses of
  the first load's s16 temp without changing semantics). Hence no site can host species (a) with `lhu` at idx 244.

### F6. Path (b) — the generic "two independent SETs" split (combine.c:1963-2020) — has no natural candidate here.
* It strands i2dest when I1's dest stays live and I3' folds I1's SOURCE away into one insn. cse (before flow) already
  folds constant pointer offsets (`fold_rtx` PLUS-of-equivalent-PLUS; probes ghost3/ghost4: `p=a+3; q=p+2; *q` → `lw 20($4)`
  with no ghost), so only combine-only simplifications (shift/mask/extend algebra) can do the folding, and the fold must
  yield ONE MIPS insn not mentioning I1's dest: for a memory source that is only lh/lb (= species (a)); for a register
  source the target's shift/mask chains (`andi/sll/sra` on u18, `srl/sll` on d, `andi/srl` on flags, `sll` on w, the
  synth_mult sequences) all keep their intermediates as real instructions (a stranded temp would REMOVE an insn from the
  stream, but every insn in the target is accounted for by the byte-exact lhu draft).
* m_split (mips.md define_split) path: no large-constant adds in this function; the only wide constant (0x6009F) is a
  plain `li`.

### F7. Verdict on HYPOTHESIS.md and on the residual.
* The caller-save-area reading is refuted at two points: (1) the spill register is chosen once, before the loop, from
  zero-use regs first, so a pseudo homed in $t0 would move every reload to $t1 (F1); (2) a caller-save area needs
  `caller_save_needed`, i.e. an allocno that took the profitability path, which is then homed in a call-used reg through
  the final code and saved/restored at every call it is live across — the target has neither.
* The residual IS a ghost pseudo (an 8-byte alter_reg slot for a pseudo with stale flow refs and no occurrences; F4), and
  the only ghost producer reachable from C in this compiler for a memory value is the SIGN_EXTEND narrow-load split, whose
  visible signature is `lh`. The byte at idx 244 is `lhu`. Unless the original source contains a stranded temp from a
  fold I have not enumerated (F6 lists what the code stream rules out), the pair {lhu at idx 244, frame 0x78} is not
  reachable by re-spelling this computation — consistent with §172's wall statement and S79's ~200 probes.
* Best drafts: TU-clean `.run/P32/t5x/fable/func_80032A74.c` (rtu DIFF 1, `lh` vs `lhu`, frame exact) and the code-exact
  `.run/P32/t4b/func_80032A74/lhu.c` (frame 0x70, 22 offset rows).
