## 1. The residual's mechanism, as read in the compiler (not as guessed)

The prior five sessions read the `mflo $a2` as local-alloc reusing the multiplier's dying register
(`combine_regs` / `qty_phys_sugg`). Both instruments say otherwise:

1. **The `mflo` is a reload, and the mult results are GLOBAL allocnos.** `mulsi3_internal`
   (`tools/reference/gcc-2.7.2/config/mips/mips.md:848`) sets operand 0 with constraint `=l` (LO).
   The `-dl` dump lists every mult result as `pref LO_REG, else GR_REGS` and NONE of pseudos 90–102 appear
   in local-alloc's `;; Register N in M` list; the `-dg` dump opens with `;; 13 regs to allocate: 92 97 99
   100 102 91 93 94 95 96 101 90 98` — they are allocated by `global.c`. Reload then emits the
   `(set (reg N) (reg 65 lo))` output reload that prints as `mflo` (`.greg`: `(insn 228 136 142 (set (reg/v:SI
   8 t0) (reg:SI 65 lo)) -1 …)` in the pinned draft).
2. **global.c parks three mult results in LO itself, and reload RETRIES them.** `find_reg` is first
   called with the preferred class (`global.c:565-572`); LO_REG contains only reg 65, which is neither fixed
   (`mips.h:1186` FIXED_REGISTERS) nor in the mult's clobbers (hi=64 and accum=66 are, lo is the dest), so
   m3 (92), m8 (97) and m13 (102) — mutually non-conflicting — all get LO. Reload needs LO for insn 49's
   output → `Spilling reg 65.` (and `Spilling reg 16.` for insn 87's GR_REGS input need — that unused
   `$s0` is why the target saves an `$s0` it never uses) → `spill_hard_reg` calls
   `retry_global_alloc (i, forbidden_regs)` in pseudo order: `Register 92 now in 7.` / `Register 97 now in
   17.` / `Register 102 now in 8.` (pinned draft) — the target's m3=$a3, m8=$s1 are these very retries.
3. **The pin forbade `$a2` at retry.** `retry_global_alloc` passes `forbidden_regs` as `losers` to `find_reg`
   (`global.c:904-937`, `IOR_HARD_REG_SET (used1, losers)`). `forbidden_regs` is seeded from `bad_spill_regs`
   (`reload1.c:709`), which contains every reg in `regs_explicitly_used` (`reload1.c:3651-3660`, the
   `#ifndef SMALL_REGISTER_CLASSES` branch MIPS takes), and `regs_explicitly_used` is a copy of
   `regs_ever_live` at reload entry (`reload1.c:486`) — i.e. the hard regs written explicitly in the RTL:
   parameters, sp, the mult clobbers, and **`register s32 e0 __asm__("$6")`**. At 102's retry its conflicts
   are `2 3 5 7 11` (dump line `;; 102 conflicts: 94 95 96 98 101 102 2 3 5 7 11 29 64 66`) plus the regs of
   the already-placed 94/95/96/98/101 (13/14/15/25/**4**); first fit in numeric order is therefore `$a2`(6)
   — unless `$a2` is forbidden, in which case it is `$t0`(8). The target's source had no pin.

So the residual was not a variable-reuse, a birth point, or a tie: it was the FIRST lever of the S76
session (the pin, 51→20) poisoning the LAST allocation decision.

## 2. Getting e0 into `$a2` without a pin (local-alloc first-fit)

Unpinned, the S79 draft regresses to 37: e0 (pseudo 80) goes to `$v1`, tbl to `$a2`. Read from `-dl`:
local-alloc ties `{e0, e0<<16, lo0}` into one quantity (each source dies at the next insn, `combine_regs`),
10 refs over 38 insns → `qty_compare` (`local-alloc.c:1579`) priority `floor_log2(10)·10/38·10000 = 7894`;
e1's quantity `{e1, -e1}` is 5 refs / 15 → 6666. Higher priority allocates first, first fit takes the lowest
free register (no `REG_ALLOC_ORDER` on MIPS 2.7.2). With e0 first, `$v1` is free over [12,50] and e0 takes it.
The target's allocation requires e1's quantity FIRST (it then occupies `$v1` inside e0's range, so e0
falls through `$v0/$v1/$a0/$a1` to `$a2`), and e0 still ahead of tbl (76, 4/15 → 5333) or tbl takes `$a2`.
I derived the full constraint set from the target's bytes by inverting first-fit (report §4) — the only
inversion needed is e1 > e0.

**Lever:** a zero-byte launder on e1, `__asm__("" : "=r"(e1) : "0"(e1));`, adds two refs to e1's
quantity (7 refs / 16 → 8750). Placement is the whole game:
* right after `e1 = *(s32*)addr1` → sched1 puts the asm at position 27 → closeness **15**: it lengthens
  lo1 (87: 4 refs, [23,39]) by one insn, breaking the EXACT tie lo1 (8/32=2500) vs p_ab (103: 3/12=2500)
  that the stable qsort had resolved in lo1's favour → p_ab takes `$a0`, lo1 → `$a3`, cascade.
* immediately before `dst[6] = -e1` (or after `hi1 = e1 >> 16`) → the asm is placed at position 40, after
  lo1's death at the m12 mult → closeness **6**, and the whole LOCAL allocation now equals the target's, and
  `Register 102 now in 6` — the `mflo $a2` residual is gone.

## 3. The last 3 rows: a global-allocno tie the launder created, and its zero-byte repair

The pos-40 asm lies inside m6/m7/m12's ranges (95/96/101: 23 → 24 insns, `allocno_compare` pri 869 → 833)
but not m1's (90: [15,38], 24 insns, 833). The former strict order `95 96 101 90` becomes a 4-way tie broken
by allocno number (`global.c:605-609`) → 90 first → `$t6/$t7/$t8` rotate (idx 17/44/48). Repair: one more
zero-byte insn inside m1's range but outside lo1's `[23,39]` and before m2's birth (17), i.e. sched1
positions 16–22: `__asm__("" : "=r"(p1) : "0"(p1));` between `p1 = src[1] & 0xFFF` and `addr1 = (p1<<2)+tbl`
lands at position 20 (it is glued between the `andi` and the `sll` of the p1 chain). Every local
`qty_compare` was recomputed with the +1 (tbl 5333→5000, lo2 4545→4347, hi0/hi2/p_ac shifted alike) — no
relative order changes; the global order returns to `92 97 99 100 102 91 93 94 95 96 101 90 98` — and
match_one/rtu_match both say MATCH. Laundering `addr1` right after its `addu` (position 22) also matches
byte-for-byte (kept as `.run/P32/t5x/work/func_80020DA4/v3c/draft.c`).

## 5. Generalizable lessons (for the cookbook harvest)
* **A pinned hard register is FORBIDDEN to every `retry_global_alloc`** (reload1.c:486 → 3651 → 709 →
  3497). Symptom: a `mflo`/reload destination that first-fit should have given the pinned register's
  freshly-dead slot lands one register higher. The pin that fixed an early allocation can be the sole cause
  of a late one; unpin and reproduce the allocation with priority levers instead.
* **On MIPS 2.7.2 every `mult` result is a GLOBAL allocno** (pref class LO_REG, `=l`), first parked in LO
  by `find_reg`'s preferred-class pass, spilled by reload, retried in PSEUDO-NUMBER order with the
  post-first-pass conflicts. `Spilling reg 16` for the GR input reload is why `$s0` is saved-but-unused
  in this function (and presumably its siblings).
* **Launder placement is a sched1 question, not a source-order one:** an in-place `"0"` launder is placed
  right after its input's last reader when a consumer needs it early, and right before its consumer when
  nothing else does; check `-dl` for the position and re-run every `qty_compare` that spans it — one insn
  splits an exact tie (§47) in either direction.
* The `-dg` header (`regs to allocate`, `conflicts`, `Spilling`, `now in`) plus `-dl`'s `used N times across
  M insns` are sufficient to predict first-fit by hand for a straight-line function; the inversion of the
  target's bytes into "who was allocated before whom" gave the exact priority window (5333 < e0 < e1).
