## The three mechanisms (read from -dS/-dR/.combine/.greg dumps + compiler source; each measured both ways)

### A. Frame 0x70 vs 0x60 = two combine USE-orphans of the `mode` promotion (§172 producer 2) — 46 -> 24
The prior report's "two reload slots its code never touches, unreachable from C" was the right SYMPTOM and the wrong producer.
* The record's mode halfword is an **s16 read from memory at every use** — `*(s16 *)(c - 0x1F) & 0xC000` for the branch and
  `*(s16 *)(c - 0x1F) & 0xFFF` inside EACH clamp arm (textual repeats, §172a). No `mode` variable.
* mips.md:2340 `extendhisi2`: under `optimize` the HImode MEM is `force_not_mem`'d into `(reg:HI m)` and promoted through
  `temp = m<<16; p = temp>>16` (gen_ashlsi3/gen_ashrsi3). The arm's `& 0xFFF` is C-shortened to an HImode AND that expands as
  `(and:SI (subreg:SI (reg:HI m)) 4095)` (seen in `.rtl`), so m has a second use.
* combine's 3-way merge of load+ashift+ashiftrt makes the `lh` (`extendhisi2_internal`); because m is still used,
  `added_sets_1` (combine.c:1460/1664) keeps m; the ashift `temp` (reg 135 / 205 in the dumps) loses its setter and its
  REG_DEAD note finds no home — distribute_notes (combine.c ~10835: "we have hit a CODE_LABEL, insert a USE insn") emits
  `(insn 840 154 156 (use (reg:SI 135)))` right after the `bnez flag` jump. reload1.c alter_reg gives the never-referenced

* The memory-re-read spelling also yields the target's `addu $v1,$v0,$zero`: the HI value is re-materialised as a copy of the

* Measured: `s32 mode` var, arm-duplicated: frame 96, 0 USE, 344 ins/269 (c); `s32 mode` var, t once: 96/0 USE/54 (d);

### B. The DR_TPAGE block: one scratch variable carries the len byte AND the tpage word — 24 -> 16
Target: `li $v1,1; sb $v1,3($v0); sll $v1,$s0,5; andi; lui $a0; or $v1; sll $a0,$s1,2; lw $a1,0($v0); addu; sw $v1,4($v0)`.
Mine: the tpage chain first, tied into `$s0`, then `li/sb`.
* sched.c is a BACKWARD list scheduler (schedule_block: `NEXT_INSN (insn) = last; last = insn` — each pick is linked before the
  previous one). rank_for_schedule: priority (depth from block start, `priority()`), then class vs last_scheduled_insn, then
  LUID (higher LUID picked first = placed later). schedule_select then moves the ready insn with the largest
  `potential_hazard` to the front — every memory-unit insn in a block with >= 2 memory insns beats every ALU insn at equal
  priority (`unit_n_insns` is the block's count, incremented in prepare_unit from priority(), never decremented).
* `-dS` trace (v_l): picks J(sw tp) I(addu) H(lw tag) then **B(sb) "has a greater potential hazard"** over G/F, then A
  (birthing-boosted `li 1`, adjust_priority -> 7f000001), then the tpage chain. So `tp` is live across `li 1`/`sb`, they
  cannot share `$v1`, and with `n` pinned the chain's dest ties into the dying hard reg `$s0` (local-alloc combine_regs'
  hard-reg branch, §501-C).
* The target's order J I H G F E D C B A is only possible if the `sb` is NOT READY after the tag load: it needs a successor in
  the tpage chain. Spelling `tp = 1; q[3] = tp; qt = *(u32 *)q; tp = ((n << 5) & 0x9FF) | 0xE1000000; *(u32 *)(q + 4) = tp;`
  gives the `sb` an ANTI-dependence on the `or` (it reads the pseudo the `or` sets), makes `tp` 2-set (no birthing boost —
  the `or` is not glued to its store, matching the target's F..J gap) and puts both values in one pseudo -> `$v1`.
  Same game idiom already banked at `src/800.c:3826-3832` (a scratch `one` beside the tpage word).
* `n` must be UNPINNED for this block (a global allocno is never tied by local-alloc; global.c still gives it `$s0`):
  s1 (n pinned) 21, **s2 (n unpinned) 16**, s3 (scratch = the `$3`-pinned `w`) 21. Unpinning n alone (l) 28; n+otz (m) 46.

### C. `la $a0, D_800AF648` first in the prologue — 16 -> MATCH
* sched2 input order (post-reload): prologue `addiu sp` + saves (regno-descending, mips.c save_restore_insns:93), then the
  body in sched1 order. Backward picks with ties by highest LUID mean **the body insn with the lowest LUID is placed first**
  (`-dR` trace v_l: T-11 picks 46 after 36 and before 30/25/20/15/848/9 — exactly its post-sched1 position). The saves sit
  right before their anti-dependent defs because each `sw` becomes ready when its def is placed and wins the hazard rule.
* So the address must be the FIRST body insn: `arg = &D_800AF648;` as the first statement. Plain (p1, `$4`-pinned; zc,
  unpinned) is INERT at 24/16: `.rtl` shows insn 9 `(set (reg 4) (symbol_ref))` first and insn 47 `(set (reg 4) (reg 4))` at
  the call; `.cse` adds `REG_EQUAL (symbol_ref)` to 47; `.combine` shows 47 rewritten to `(set (reg 4) (symbol_ref))` and 9
  deleted — combine substitutes the constant into the call-site copy (the prior report's "the arg setup is emitted at the
  call site even when hoisted", now with the pass named).
* The zero-byte `__asm__("" : "=r"(arg) : "0"(arg))` after the assignment blocks the substitution; the call's argument copy

## Cookbook-worthy generalisations (for the harvest)
1. **A frame that is +8k with slots no instruction touches is combine USE-orphans, and it IS reachable from C**: an s16
   promoted twice from MEMORY (not from a variable) makes one orphan per promotion site; the same spelling produces the
   `addu $v1,$v0,$zero` copy where an `s16` variable would re-load. Count `(use (reg` insns in `.combine` (§172 instrument).
2. **The sched.c hazard rule makes a ready store beat any ALU insn**; when a target orders ALU work before a store whose only
   successor was just placed, the store must have a LATER successor — look for a SHARED VARIABLE between the stored value and
   the later computation (anti-dependence). A scratch variable reused for a constant byte and a computed word is a real game
   idiom (src/800.c:3826).
3. **Prologue "argument first" = lowest body LUID, and combine (not cse) undoes a first-statement address by substituting the
   REG_EQUAL constant into the call-site copy** — a zero-byte launder on the variable after its assignment keeps the LUID.
4. Pins can be the wall twice over (§501-E): here a hard-register `n` handed its dying `$s0` to a temp via combine_regs; a
   global pseudo is never tied. Unpin the variable whose death feeds the mis-allocated temp.
